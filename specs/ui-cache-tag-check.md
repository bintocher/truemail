# Проверка меток версий файлов интерфейса при сборке

- Состояние: реализована
- Задача: issue #35
- Обновлено: 2026-09-05
- Ревизия: 2

## Цель и результат для пользователя

Встроенный браузер запоминает файлы интерфейса по адресу, поэтому у каждого подключаемого файла в адресе стоит метка версии. Если изменённый файл получил новое содержимое, но метку ему не подняли, после обновления программы пользователь продолжает выполнять старую копию файла: часть исправлений просто не появляется, а сочетание старых и новых файлов даёт ошибки, которые невозможно воспроизвести у разработчика.

Сейчас это правило держится на внимательности: при подготовке версии 0.2.6 метку пропустили дважды, и оба раза ошибку нашло ревью, а не проверка. После изменения такую ошибку находит сборка: изменение файла интерфейса без поднятой метки не проходит проверку.

## Границы задачи

- Новый скрипт проверки в каталоге `scripts/`.
- Шаг проверки в `.github/workflows/ci.yml`.
- Цель запуска проверки в `Makefile`.

## Что не входит в задачу

- Автоматическая простановка меток версий.
- Отказ от меток в пользу другого способа обновления кэша.
- Проверка меток в собранном пакете программы.

## Текущее поведение и доказательства

- Файлы интерфейса подключаются с меткой версии в адресе: 18 подключений с `?v=` в `apps/desktop/ui/index.html`, в том числе `theme-init.js?v=20260731-1` (строка 7), `styles.css?v=20260902-3` (строка 8) и модули (строки 689-704).
- Файлы локализации подключаются не из разметки, а запросом внутри кода: `fetch('locales/${locale}.json?v=20260807-1')` (`apps/desktop/ui/modules/i18n-onboarding.js:4`).
- Окно уведомления подключает свой файл отдельно: `notify.js?v=20260808-1` (`apps/desktop/ui/notify.html:58`).
- В `.github/workflows/ci.yml` есть шаги проверки форматирования, статического анализа, проверок Rust и проверок JavaScript; проверки меток версий нет.

## Термины и состояния

- Метка версии - значение параметра `v` в адресе подключаемого файла интерфейса.
- Базовая ветка - ветка, с которой сравнивается набор изменений: для запроса на слияние это его целевая ветка, для сборки ветки разработки - её предыдущее состояние.
- Подключающий файл - файл, в котором записана метка версии: `apps/desktop/ui/index.html` для большинства файлов, `apps/desktop/ui/notify.html` для окна уведомления, `apps/desktop/ui/modules/i18n-onboarding.js` для файлов локализации.

## Требования

### S-001. Проверка меток изменённых файлов

WHEN набор изменений содержит изменённый файл интерфейса, у которого есть метка версии в подключающем файле, проверка SHALL требовать, чтобы значение этой метки отличалось от значения в базовой ветке.

### S-002. Отказ сборки при неподнятой метке

IF изменённый файл интерфейса сохранил прежнюю метку версии или потерял её вовсе, THEN проверка SHALL завершиться ошибкой и назвать этот файл и его подключающий файл.

### S-003. Файлы локализации

WHEN изменён файл в `apps/desktop/ui/locales`, проверка SHALL требовать изменения метки версии в строке запроса локализаций в `apps/desktop/ui/modules/i18n-onboarding.js`.

### S-004. Изменения вне интерфейса

IF набор изменений не содержит файлов из `apps/desktop/ui`, THEN проверка SHALL завершиться успешно.

### S-005. Файлы без подключения по адресу

IF изменённый файл интерфейса не подключается по адресу с меткой версии, THEN проверка SHALL пропустить его без ошибки.

### S-006. Удалённые файлы

IF файл интерфейса удалён в наборе изменений, THEN проверка SHALL пропустить его без ошибки.

### S-007. Запуск вручную

Проверка SHALL запускаться отдельной целью сборочного файла с указанием базовой ветки.

### S-008. Понятный отчёт

WHEN проверка завершается ошибкой, проверка SHALL вывести перечень всех файлов с неподнятыми метками, а не только первый из них.

## Интерфейсы и данные

- Скрипт проверки принимает имя базовой ветки или ссылку на состояние сравнения; при отсутствии параметра берёт целевую ветку запроса на слияние, а для ветки разработки - её предыдущее состояние.
- Скрипт возвращает код 0 при успехе и ненулевой код при нарушении.
- Соответствие "файл интерфейса - подключающий файл" определяется поиском подключения по имени файла в `index.html` и `notify.html`, а для локализаций - строкой запроса в `i18n-onboarding.js`.

## Ошибки и частичные отказы

- Если базовая ветка недоступна в рабочей копии (неполная выгрузка истории), скрипт запрашивает недостающую историю; при неудаче завершается ошибкой с понятным сообщением, а не пропускает проверку молча.

## Одновременная работа, повторы и защита от дублей

- Проверка не меняет файлы и может выполняться параллельно с другими шагами сборки.

## Безопасность и конфиденциальность

- Скрипт читает только содержимое репозитория и не обращается в сеть, кроме запроса недостающей истории у того же репозитория.

## Совместимость, перенос данных и откат

- Изменение затрагивает только сборку; на работу программы у пользователя не влияет.

## Скорость и потребление ресурсов

- Проверка сравнивает перечень изменённых файлов и несколько строк подключающих файлов, поэтому занимает секунды.

## Журналы, метрики и эксплуатация

- Скрипт выводит перечень проверенных файлов и итог проверки в вывод сборки.

## Отклонённые варианты

- Проставлять метку автоматически при сборке. Скрывает изменение состава файлов от ревью и делает содержимое сборки зависимым от времени запуска.
- Складывать все файлы интерфейса в один и раздавать одной меткой. Ломает раздельную отладку файлов и увеличивает объём изменений.
- Отказаться от меток и запретить кэш заголовками ответа. Файлы отдаются встроенным протоколом программы, а не сервером; управление заголовками там не настраивается.
