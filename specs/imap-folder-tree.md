# Дерево почтовых папок IMAP

- Состояние: реализована
- Задача: issue #137
- Обновлено: 2026-11-24
- Ревизия: 1

## Цель и результат для пользователя

Подпапки в ящиках Яндекса видны под своими родителями. В списках выбора вложенную папку можно узнать по полному пути, а папки с одинаковой ролью можно различить по серверным именам.

## Границы задачи

- Разбор списка папок IMAP и чтение родителя из ответа JMAP.
- Сохранение связей в существующей колонке `folders.parent_id`.
- Панель папок, сопоставление папок, состав источников, выбор папок в правилах и быстрых действиях.

## Что не входит в задачу

- Изменения в получении папок Gmail и Exchange.
- Изменение схемы базы данных.

## Текущее поведение и доказательства

До исправления `list_oauth_folders` делила имя по символам `/` и `|` и оставляла `parent_remote_path` пустым. Поэтому панель показывала дочерние папки Яндекса с отступом в плоском списке. Например, `Удаленные|pending` оказывалась в стороне от папки "Удаленные".

Яндекс отдаёт разделитель `|` в ответе `LIST` и кодирует кириллические имена в modified UTF-7. В одном из проверенных ящиков есть папки "Архив" и "Archive" с ролью архива, в другом - "Черновики" и "Drafts" с ролью черновиков. До исправления обе папки каждой пары получали одинаковую подпись в панели. Exchange уже передавал идентификатор родителя, а JMAP запрашивал список папок без поля `parentId`.

## Термины и состояния

- Серверный путь `remote_path` - полное имя IMAP либо идентификатор папки JMAP или Exchange.
- Короткое имя `display_name` - имя, по которому пользователь узнаёт саму папку.
- Родитель `parent_id` - идентификатор родительской папки в локальной базе.
- Роль - назначение папки, например черновики или архив.
- Полный путь для показа - цепочка коротких имён от корня до папки через ` / `.

## Требования

### S-001. Короткое имя IMAP

WHEN обработан элемент ответа IMAP LIST, THEN система SHALL записать в `display_name` последний сегмент серверного имени по разделителю LIST после декодирования из modified UTF-7.

### S-002. Родитель IMAP

IF серверное имя IMAP содержит разделитель из ответа LIST, THEN система SHALL записать в `parent_remote_path` серверный путь до последнего вхождения этого разделителя.

### S-003. Плоское имя IMAP

IF ответ IMAP LIST содержит NIL вместо разделителя или серверное имя не содержит объявленного разделителя, THEN система SHALL обрабатывать серверное имя как один сегмент.

### S-004. Роль IMAP по имени

WHERE папка IMAP вложена, система SHALL определять её серверную роль только по атрибутам LIST.

### S-005. Родитель JMAP

WHEN получен `Mailbox.parentId` со значением, отличным от null, THEN система SHALL передавать его как `parent_remote_path` при обнаружении папок JMAP.

### S-006. Обновление локальной связи

WHEN сохранён обновлённый список папок, THEN система SHALL пересчитать `parent_id` сохранённых в этом списке папок по серверному пути родителя в том же ящике.

### S-007. Вложенность в панели

WHERE родитель доступен в панели папок, система SHALL показывать ветку подпапок сразу под ним с отступом по глубине.

### S-008. Папка без доступного родителя

IF родитель отсутствует в списке папок ящика, THEN система SHALL показывать папку в панели на верхнем уровне.

### S-009. Порядок папок верхнего уровня

WHILE панель показывает верхний уровень ящика, система SHALL располагать папки с ролями в порядке входящие, отправленные, черновики, архив, спам, удалённые перед папками без роли.

### S-010. Порядок подпапок

WHERE подпапки имеют общего родителя, система SHALL сортировать их по короткому имени.

### S-011. Полный путь в плоском списке

WHERE вложенная папка перечислена в сопоставлении папок, составе источников, правилах или быстрых действиях, система SHALL показывать её полный путь для показа.

### S-012. Подпись папки с общей ролью

IF в одном ящике несколько папок с одной ролью, THEN система SHALL использовать серверное имя каждой из них при показе короткой подписи.

### S-013. Подпись папки с единственной ролью

IF в одном ящике роль назначена ровно одной папке, THEN система SHALL показывать локализованное название роли там, где короткая подпись строится по роли.

## Интерфейсы и данные

- `list_oauth_folders` передаёт имя и разделитель LIST в `imap_list_folder`. Серверный путь сохраняется в исходном виде, чтобы найти родителя по точному совпадению.
- `Mailbox/get` запрашивает `parentId` вместе с уже используемыми полями. Его значение соответствует `Mailbox.id` родителя.
- `save_discovered_folders` разрешает ссылки после записи всех полученных папок в одной транзакции. Если путь родителя отсутствует или папка с этим путём не найдена в ящике, `parent_id` равен NULL.
- `folderTreeRows` использует `parent_id` для навигации. `folderPathLabel` собирает пути для плоских списков по той же связи. Для прежних записей IMAP без связи остаётся разбор уже сохранённого пути по `/` и `|`.
- Структуры команд интерфейса и схема базы сохраняются.
