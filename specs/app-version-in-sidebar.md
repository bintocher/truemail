# Версия программы внизу боковой панели

- Состояние: реализована
- Задача: issue #54
- Обновлено: 2026-09-09
- Ревизия: 5
- Утвердил: владелец репозитория
- Дата утверждения: 2026-09-09

## Цель и результат для пользователя

Пользователь не видит, какая версия программы у него установлена, пока не откроет настройки и не нажмёт проверку обновлений - а она идёт в сеть и сообщает версию только вместе с ответом сервера обновлений. Заметки к выпуску при этом не открыть вовсе.

После изменения номер установленной версии виден внизу боковой панели, под списком аккаунтов, всегда. Он читается из данных установленной программы, поэтому сети для показа не нужно. Нажатие на него открывает страницу этого выпуска на GitHub в браузере по умолчанию - это единственное обращение наружу, и происходит оно только по нажатию.

## Границы задачи

Задача добавляет подпись с версией в боковую панель окна почты (apps/desktop/ui/index.html), её оформление (apps/desktop/ui/styles.css), поведение (apps/desktop/ui/modules/window-chrome.js), подсказку в словарях (apps/desktop/ui/locales/ru.json и en.json), метод моста (apps/desktop/ui/bridge.js) и команду приложения, отдающую версию (apps/desktop/src-tauri/src/commands.rs, регистрация в main.rs).

## Что не входит в задачу

- Проверка и установка обновлений: кнопка в строке заголовка и раздел настроек не меняются.
- Раздел "О программе" и показ версии где-либо ещё.
- Показ версии ядра, версии сборки, отметки времени сборки и номера сборки.
- Проверка того, что выпуск с такой меткой на GitHub существует.
- Показ заметок к выпуску внутри программы.

## Текущее поведение и доказательства

Версия приложения известна ядру: она приходит из данных пакета и уже возвращается вместе с ответом проверки обновлений (`check_for_update` в apps/desktop/src-tauri/src/commands.rs). Отдельной команды, которая отдаёт только версию и не обращается к сети, нет.

В интерфейсе версия нигде не показывается: в apps/desktop/ui/index.html подписи с номером версии нет, а в настройках номер появляется лишь в строке состояния после нажатия кнопки проверки обновлений (apps/desktop/ui/modules/settings.js).

Внешние ссылки интерфейс открывает через команду `open_external_url`: встроенный веб-просмотр по обычной ссылке ничего не откроет, потому что открытие в новом окне в нём запрещено. Команда пропускает только адреса http и https.

Модули интерфейса подключаются в конце index.html по порядку; мост `window.tm` создаёт bridge.js, подключённый последним, - позже window-chrome.js.

Метки версий файлов интерфейса в index.html обязаны подниматься при изменении файла, иначе встроенный браузер возьмёт старую копию, а проверка scripts/check-ui-cache-tags.js не пройдёт.

## Термины и состояния

Подпись версии - кнопка внизу боковой панели, показывающая номер установленной версии в виде "v" и номера, например "v0.2.12".

Страница выпуска - адрес вида `https://github.com/bintocher/truemail/releases/tag/v<номер>` на GitHub.

Мост - объект `window.tm`, через который интерфейс вызывает команды приложения.

## Требования

### S-001. Версия видна внизу боковой панели

WHEN окно почты загружено, система SHALL показать внизу боковой панели, ниже списка аккаунтов и меток, номер установленной версии в виде "v" и номера версии.

### S-001a. Показ не зависит от сети

WHILE окно почты открыто, система SHALL показывать номер версии независимо от наличия сети, состояния сервера обновлений и того, опубликован ли выпуск с этим номером.

### S-002. Приложение отдаёт номер версии и адрес её выпуска

WHEN интерфейс запрашивает сведения о версии, система SHALL вернуть две величины: номер установленной версии и адрес страницы её выпуска.

### S-002a. Сведения о версии берутся без обращения к сети

WHEN интерфейс запрашивает сведения о версии, система SHALL взять их из данных установленной программы, не обращаясь к сети.

### S-002b. Адрес выпуска собирает приложение

Система SHALL собирать адрес страницы выпуска в приложении, а не в интерфейсе.

### S-002c. Интерфейс хранит полученные сведения у подписи

WHEN интерфейс получил номер версии и адрес выпуска, система SHALL сохранить обе величины у подписи версии на всё время работы окна.

### S-002d. Нажатие открывает сохранённый адрес

WHEN пользователь нажимает подпись версии, система SHALL открыть сохранённый адрес выпуска, не собирая его заново.

### S-003. Нажатие открывает страницу выпуска во внешнем браузере

WHEN пользователь нажимает подпись версии, система SHALL открыть страницу выпуска установленной версии в браузере по умолчанию.

### S-003a. Обращение наружу только по нажатию

Система SHALL обращаться наружу только по нажатию подписи версии; показ номера обращений в сеть не выполняет.

### S-004. Номер запрашивается по готовности документа

WHEN документ окна загружен, система SHALL запросить номер версии.

### S-004a. Запрос повторяется, пока мост не готов

WHILE метод моста, отдающий версию, недоступен, система SHALL повторять запрос с задержкой, пока не исчерпает предел повторов.

### S-004b. Неудача попадает в журнал

IF после исчерпания повторов версию получить не удалось или команда завершилась ошибкой, THEN система SHALL записать причину в журнал приложения.

### S-004c. Подпись видна при прокрутке панели

WHILE список папок длиннее панели, система SHALL показывать подпись версии прижатой к нижнему краю панели.

### S-005. Без доступного моста обращения не происходит

IF метод моста, отдающий версию, недоступен, THEN система SHALL NOT обращаться к нему.

### S-006. Без номера подписи не видно

IF номер версии получить не удалось, THEN система SHALL NOT показывать подпись версии. Это возможно только тогда, когда ядро программы не поднялось и не работает и остальной интерфейс.

### S-007. Скрытая подпись ничего не открывает

IF подпись версии не показана, THEN система SHALL NOT открывать никакого адреса.

### S-008. Номер не переводится

WHEN пользователь меняет язык интерфейса, система SHALL оставить номер версии без изменений.

### S-009. Подсказка переводится

WHEN пользователь меняет язык интерфейса, система SHALL показать подсказку кнопки на выбранном языке.

### S-010. Подпись читается в покое

WHERE выбрана светлая или тёмная тема, система SHALL показывать подпись цветом второстепенного текста этой темы.

### S-011. Подпись выделяется при наведении

WHILE указатель наведён на подпись версии, система SHALL показывать её цветом выделения выбранной темы.

### S-012. Наружу уходит только адрес выпуска

Система SHALL открывать по нажатию только адрес страницы выпуска на GitHub, собранный из постоянной части и номера установленной версии.

## Интерфейсы и данные

Команда приложения `app_version` возвращает две величины: номер версии из данных пакета и адрес страницы её выпуска вида `https://github.com/bintocher/truemail/releases/tag/v<номер>`. Постоянная часть адреса задана в приложении. Метод моста `appVersion` вызывает эту команду. Открытие ссылки идёт через существующую команду `open_external_url`, которая пропускает только http и https.

Интерфейс сохраняет обе величины у подписи версии: номер показывается, адрес используется при нажатии. Заново адрес не собирается, поэтому вид адреса задан в одном месте.

Подпись версии - кнопка в боковой панели с постоянным идентификатором. Её текст ставит интерфейс, поэтому словарь перевода её не трогает; подсказка задаётся ключом словаря и переводится наравне с прочими подсказками.

Схема базы, настройки и прочие команды моста не меняются.

## Ошибки и частичные отказы

Если команда вернула ошибку, подпись остаётся пустой и скрыта правилом оформления (S-006); в журнал веб-просмотра попадает ошибка.

Если метода моста нет вовсе (ядро не поднялось), запрос не выполняется, подпись остаётся скрытой, записи в журнал не появляется: в этом случае не работает и остальной интерфейс.

Если команда не ответила и не завершилась ошибкой, подпись остаётся скрытой до конца работы окна. Отдельного времени ожидания задача не вводит: оно общее для всех команд моста.

Если выпуска с такой меткой на GitHub нет (сборка из исходников, версия поднята до выпуска), браузер покажет страницу GitHub с сообщением об отсутствии страницы. Программа при этом ничего не сообщает и продолжает работу.

Если открыть браузер не удалось, интерфейс показывает всплывающее сообщение с текстом ошибки - так же, как прочие внешние ссылки.

## Одновременная работа, повторы и защита от дублей

Номер запрашивается один раз по готовности документа. Повторные нажатия открывают ту же страницу; ограничения на частоту нажатий задача не вводит.

## Безопасность и конфиденциальность

Наружу уходит только адрес страницы выпуска. Номер версии приходит из данных пакета, пользовательских данных в адресе нет. Открытие идёт через команду, которая пропускает только веб-адреса.

## Совместимость, перенос данных и откат

Схема базы и настройки не меняются: сведения о версии не сохраняются на диск, они живут только в памяти окна. Откат - удаление подписи, её оформления, метода моста, команды и её регистрации в apps/desktop/src-tauri/src/main.rs.

Метки версий изменённых файлов интерфейса поднимаются вместе с изменением файлов: у модулей и таблицы стилей - в index.html, у словарей - в адресе их загрузки в apps/desktop/ui/modules/i18n-onboarding.js.

## Скорость и потребление ресурсов

Один вызов команды по готовности документа. Команда читает данные пакета, к сети и к базе не обращается, дополнительных запросов не появляется.

## Журналы, метрики и эксплуатация

Новых записей журнала и метрик задача не вводит. Ошибка получения версии попадает в журнал веб-просмотра.

## Отклонённые варианты

Брать версию из ответа проверки обновлений. Отклонено: этот путь обращается к сети, а версия нужна сразу при запуске и без сети.

Показывать версию в настройках вместо боковой панели. Отклонено решением владельца: номер нужен на виду, без открытия настроек.

Вести ссылку на общий список выпусков. Отклонено: пользователю нужны заметки именно к своей версии.

Проверять наличие выпуска перед открытием ссылки. Отклонено: это обращение к сети ради подсказки, а страница отсутствующего выпуска и так понятна.
