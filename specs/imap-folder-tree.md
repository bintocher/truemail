## Цель и результат для пользователя

Подпапки в ящиках Яндекса видны под своими родителями. В списках выбора вложенную папку можно узнать по полному пути, а папки с одинаковой ролью можно различить по серверным именам.

## Границы задачи

- Разбор списка папок IMAP и чтение родителя из ответа JMAP.
- Сохранение связей в существующей колонке `folders.parent_id`.
- Панель папок, сопоставление папок, состав источников, выбор папок в правилах и быстрых действиях.

## Что не входит в задачу

- Изменения в получении папок Gmail и Exchange.
- Изменение схемы базы данных.

## Текущее поведение и доказательства

До исправления `list_oauth_folders` делила имя по символам `/` и `|` и оставляла `parent_remote_path` пустым. Поэтому панель показывала дочерние папки Яндекса с отступом в плоском списке. Например, `Удаленные|pending` оказывалась в стороне от папки "Удаленные".

Яндекс отдаёт разделитель `|` в ответе `LIST` и кодирует кириллические имена в modified UTF-7. В одном из проверенных ящиков есть папки "Архив" и "Archive" с ролью архива, в другом - "Черновики" и "Drafts" с ролью черновиков. До исправления обе папки каждой пары получали одинаковую подпись в панели. Exchange уже передавал идентификатор родителя, а JMAP запрашивал список папок без поля `parentId`. У Exchange порядок детей внутри одной группы роли становится алфавитным по короткому имени.

## Термины и состояния

- Серверный путь `remote_path` - полное имя IMAP либо идентификатор папки JMAP или Exchange.
- Короткое имя `display_name` - имя, по которому пользователь узнаёт саму папку.
- Родитель `parent_id` - идентификатор родительской папки в локальной базе.
- Роль - назначение папки, например черновики или архив.
- Полный путь для показа - цепочка коротких имён от корня до папки через ` / `.

## Требования

### S-001. Короткое имя IMAP

WHEN обработан элемент ответа IMAP LIST, THEN система SHALL записать в `display_name` последний сегмент серверного имени по разделителю LIST после декодирования из modified UTF-7.

### S-002. Родитель IMAP

IF серверное имя IMAP содержит разделитель из ответа LIST, THEN система SHALL записать в `parent_remote_path` серверный путь до последнего вхождения этого разделителя.

### S-003. Плоское имя IMAP

IF ответ IMAP LIST содержит NIL вместо разделителя или серверное имя не содержит объявленного разделителя, THEN система SHALL обрабатывать серверное имя как один сегмент.

### S-004. Роль IMAP по имени

WHEN обработана папка IMAP, THEN система SHALL брать роль из атрибутов LIST, а при отсутствии роли в атрибутах определять её по короткому имени только у папки верхнего уровня или папки непосредственно внутри INBOX. Имя INBOX сравнивается без учёта регистра.

### S-005. Родитель JMAP

WHEN получен `Mailbox.parentId` со значением, отличным от null, THEN система SHALL передавать его как `parent_remote_path` при обнаружении папок JMAP.

### S-006. Обновление локальной связи

WHEN сохранён полный список папок ящика, THEN система SHALL устанавливать `parent_id` только по точному совпадению серверного пути родителя с папкой из этого списка и записывать NULL, если совпадения нет.

### S-007. Вложенность в панели

WHERE родитель доступен в панели папок, система SHALL показывать ветку подпапок сразу под ним с отступом по глубине.

### S-008. Папка без доступного родителя

IF родитель отсутствует в списке папок ящика или принадлежит другому ящику, THEN система SHALL показывать папку в панели на верхнем уровне.

### S-009. Порядок папок на всех уровнях

WHEN панель упорядочивает корневые папки или подпапки одного родителя, THEN система SHALL располагать их по ролям в порядке входящие, отправленные, черновики, архив, спам, удалённые, затем без роли, а внутри каждой группы сортировать по `display_name` с подстановкой `remote_path` при пустом имени.

### S-010. Первое обновление после установки

WHERE после установки версии родительские связи папок IMAP и JMAP ещё не сохранены, система SHALL показывать такие папки на верхнем уровне до первого обновления списка, при котором сохраняются доступные связи.

### S-011. Полный путь в плоском списке

WHERE вложенная папка перечислена в сопоставлении папок, составе источников, правилах или быстрых действиях, система SHALL показывать её полный путь для показа.

### S-012. Подпись папки с общей ролью

IF в одном ящике несколько папок с одной ролью, THEN система SHALL использовать серверное имя каждой из них при показе короткой подписи.

### S-013. Подпись папки с единственной ролью

IF в одном ящике роль назначена ровно одной папке, THEN система SHALL показывать локализованное название роли там, где короткая подпись строится по роли.

### S-014. Сохранение подпапки при исчезновении родителя

WHEN сверка удаляет отсутствующую на сервере папку, THEN система SHALL в той же транзакции снять ссылки на неё у папок того же ящика и сохранить идентификаторы и письма подпапок, оставшихся в списке.

### S-015. Удаление отсутствующей подпапки

IF самой подпапки нет в полученном списке, THEN система SHALL удалить её локальную запись при сверке.

### S-016. Цикл в родительских связях

WHEN после обхода обычных корней остаются непосещённые папки, THEN система SHALL обходить их в порядке исходного списка, начиная каждую оставшуюся ветку с верхнего уровня и показывая каждую папку один раз. Обход на всех уровнях выполняется итеративно со стеком.

### S-017. Определение отсутствующей роли по имени

WHEN для ручного перемещения по роли требуется определить отсутствующую роль, THEN система SHALL назначать её только при единственном совпадении короткого имени среди папок верхнего уровня и папок непосредственно внутри INBOX того же ящика. Серверный путь INBOX сравнивается без учёта регистра.

### S-019. Сохранение роли при обновлении списка

WHEN список папок обновлён, THEN система SHALL сохранить прежнюю роль папки, включая назначенную вручную, если для этой папки не получена роль при обнаружении. Роль подпапки, которую старая версия определила по имени, сохраняется до ручного переназначения в настройках. Хранение источника роли вынесено в отдельную задачу.

### S-020. Полный путь без родительской связи

WHERE у папки без `parent_id` декодированный последний сегмент `remote_path` совпадает с `display_name`, система SHALL разбирать путь только по `/`, `|` или `.` перед этим сегментом и показывать декодированные сегменты через ` / `. Если совпадения с одним из этих разделителей нет, показывается короткая подпись папки.

### S-021. Разделитель внутри имени

IF сегмент подписи пути содержит ` / ` или `"`, THEN система SHALL заключать сегмент в прямые двойные кавычки и удваивать каждую двойную кавычку внутри него.

### S-022. Целевая папка в списке правил

WHEN список правил показывает действие перемещения в выбранную папку, THEN система SHALL строить подпись цели тем же способом, что и в списке выбора папок.

### S-023. Родитель из другого ящика в подписи

IF любой родитель в цепочке подписи принадлежит другому ящику, THEN система SHALL показывать короткую подпись самой папки.

### S-024. Полный путь в заголовке и сообщении о переносе

WHERE открыта подпапка или в неё перемещено письмо, система SHALL показывать полный путь в заголовке списка писем или в сообщении о переносе соответственно. Для папки верхнего уровня сохраняется короткая подпись.

### S-025. Чтение при сверке папок

WHEN система сверяет список папок, THEN система SHALL читать записи писем и ссылки на файлы ящика до открытия транзакции записи. В транзакции определяются исчезнувшие папки, снимаются ссылки их детей и удаляются исчезнувшие папки. После фиксации удаляются только файлы папок, удалённых этой сверкой.

## Интерфейсы и данные

- `list_oauth_folders` передаёт имя и разделитель LIST в `imap_list_folder`. Серверный путь сохраняется в исходном виде, чтобы найти родителя по точному совпадению.
- `Mailbox/get` запрашивает `parentId` вместе с уже используемыми полями. Его значение соответствует `Mailbox.id` родителя.
- `save_discovered_folders` разрешает ссылки после записи всех полученных папок и сохраняет прежнюю роль, если новая роль не передана.
- `folderTreeRows` использует `parent_id` для навигации. `folderPathLabel` собирает пути для плоских списков по той же связи и использует серверный путь для записей без связи.
- Структуры команд интерфейса и схема базы сохраняются.
