# Действия над черновиком

- Состояние: реализована
- Утвердил: владелец проекта (по обращению 2026-11-23, issue #133)
- Задача: issue #133
- Зависит от: undo-send.md
- Обновлено: 2026-11-23
- Ревизия: 4

## Изменения требований в ревизии 4

- Изменено S-002. Было: контекстное меню делало активным письмо под курсором, и только кнопка "Отправить" отправляла показанное письмо. Стало: кнопки панели и меню "Ещё" действуют на показанное письмо, после закрытия контекстного меню показанное письмо снова активное, над пустой областью чтения кнопки действий черновика нет. Причина: ревью Codex (второй круг) - "Удалить" и "Исходный текст" на панели действовали на письмо из меню другого письма, кнопка "Отправить" оставалась над пустой областью чтения.
- Изменено S-010. Было: исходная текстовая часть передаётся как есть. Стало: у письма без собственной текстовой части текстовая часть пуста. Причина: ревью Codex (второй круг) - текст, построенный из разметки, уходил как будто написанный.
- Изменено S-017. Было: кнопка уходила с панели после принятия письма. Стало: кнопка видна над каждым показанным черновиком, кроме тех, чьи письма уже приняты в очередь. Причина: ревью Codex (второй круг) - после отправленного черновика следующий черновик оставался без кнопки.
- Изменено S-019. Было: очередь отвечает на отправку из редактора. Стало: очередь отвечает на отправку и на запланированную отправку, повторное нажатие "Запланировать" не ставит письмо в очередь дважды. Причина: ревью Codex (второй круг) - редактор очищался, когда в нём уже было другое письмо, а второе нажатие ставило письмо в очередь второй раз.
- Изменено S-021. Было: пропускалась часть, помеченная ядром как встроенная, результат разбора без пометки применялся по прежнему правилу. Стало: ядро помечает только часть, на которую указывает ссылка картинки в теле, результат разбора без пометок разбирается заново. Причина: ревью Codex (второй круг) - файл с идентификатором части мог исчезнуть из письма, а старый результат разбора не переразбирался.
- Изменено S-022. Было: предел проверялся после чтения очередного вложения. Стало: размер, который ядро уже знает, проверяется до чтения файла, встроенные картинки считаются до вложений. Причина: ревью Codex (второй круг) - вложение читалось целиком, чтобы узнать, что оно не помещается; письмо из одних картинок не проверялось.
- Изменено S-024. Было: имя в кавычках передавалось ядру. Стало: при обратном чтении адреса кавычки и обратные слеши имени восстанавливаются, повторного экранирования нет. Причина: ревью Codex (второй круг) - имя с кавычкой получало лишние обратные слеши.
- Изменено S-029. Было: очистка применялась к телу черновика, открываемого в редакторе. Стало: очистка применяется и к телу, которое возвращается в редактор из отменённой отправки и из автосохранения, из тела удаляются классы, идентификаторы и стили, перекрывающие программу. Причина: ревью Codex (второй круг) - очистка не работала в браузере, а возвращённое тело попадало в документ без неё.
- Добавлено S-031, S-032. Отправитель письма в редакторе при обновлении данных, отказ ядра по адресу и размеру.

## Изменения требований в ревизии 3

- Изменено S-002. Было: панель следовала за активным письмом, которое выбирает и контекстное меню. Стало: панель следует за письмом, показанным в области чтения. Причина: ревью Codex - кнопка "Отправить" над текстом одного черновика отправляла другой черновик под курсором.
- Изменено S-008. Было: отправка в один клик заполняла скрытый редактор и нажимала его кнопку. Стало: письмо читается в снимок и уходит в очередь из него, редактор не участвует. Причина: ревью Codex - другое письмо в редакторе затиралось, список ящиков менял отправителя, файл из проводника попадал в письмо.
- Изменено S-014. Было: повторная отправка черновика не ограничивалась, запланированная отправка оставляла черновик. Стало: черновик, письмо которого принято в очередь, повторно не отправляется; запланированная отправка тоже убирает черновик. Причина: ревью Codex - при пропуске перемещения тот же черновик уходил в очередь второй раз.
- Изменено S-018. Было: при другом письме во время чтения черновик не отправлялся. Стало: другое письмо остаётся нетронутым, а ответ очереди не затирает письмо, начатое за время ожидания. Причина: ревью Codex.
- Изменено S-021. Было: пропускалась всякая часть с идентификатором, предел размера считался после чтения всех вложений. Стало: пропускается только часть, помеченная ядром как встроенная; предел считается до чтения следующего вложения и проверяется ядром до записи в очередь. Причина: ревью Codex - файл с идентификатором без ссылки в теле терялся.
- Изменено S-024. Было: имя с запятой передавалось без кавычек. Стало: имя со спецсимволами передаётся в кавычках, автосохранение хранит адреса списком. Причина: ревью Codex - ядро отвергало такое имя.
- Добавлено S-007, S-009, S-010, S-012, S-013, S-019, S-022, S-023, S-025, S-027, S-028, S-029. Открытое меню черновика, отправка без редактора, текстовая часть письма, отправка из редактора, другое письмо в редакторе, ответ очереди, предел размера при чтении и в ядре, адреса в автосохранении, скрытая копия для серверного интерфейса и для SMTP, очистка тела в редакторе.
- Перенесено. Требования ревизий 1 и 2 разбиты и перенумерованы по одному обязательству, соответствие идёт по названиям. Причина: машинная проверка формы спецификаций.

## Цель и результат для пользователя

Черновик - это новое письмо, которое ещё не отправили. Раньше программа показывала его так же, как входящее: над письмом стояли "Ответить", "Ответить всем", "Переслать", "В архив", "В спам", а в меню - "Заблокировать отправитель" и "Автоочистка по отправителю". Кнопки "Отправить" не было, и отправить черновик из программы было нельзя никак.

Теперь над черновиком стоят "Отправить" и "Удалить". Одно нажатие отправляет черновик с его получателями, темой, телом и вложениями. Если получателя нет, открывается редактор с содержимым черновика и подсказкой. Отправленный черновик уходит из папки "Черновики".

## Границы задачи

- Панель над письмом, меню "Ещё" и контекстное меню списка писем.
- Отправка черновика через очередь отправки: проверка адресов, предел размера письма, очередь и окно отмены.
- Чтение скрытой копии черновика из заголовков письма.
- Перемещение отправленного черновика в корзину.
- Сохранение скрытой копии в письме для серверных интерфейсов Gmail, EWS и JMAP.

## Что не входит в задачу

- Сохранение правок черновика обратно в папку "Черновики". Правки, сделанные в редакторе, живут в автосохранении редактора, пока письмо не отправлено.
- Создание нового черновика в папке на сервере.
- Набор действий для писем папок "Отправленные", "Архив", "Спам" и "Удалённые".
- Команды палитры команд и горячие клавиши ответа на открытом письме.
- Ссылка исходного черновика на операцию очереди в ядре: после перезапуска программы черновик, оставшийся в папке из-за пропуска перемещения, снова предлагается к отправке.

## Текущее поведение и доказательства

- Панель над письмом собиралась из одного перечня действий для любого письма (`apps/desktop/ui/modules/smart-rules.js`, `applyToolbar`), контекстное меню списка - из того же перечня (`apps/desktop/ui/modules/calendar-contacts.js`, `buildContextMenu`).
- У письма есть флаг черновика (`crates/core/src/model/message.rs`, `Flags::draft`), но интерфейс нигде его не читал: упоминание черновика было только в значке и названии папки.
- Полное письмо (`MessageFull`) не содержало скрытой копии: она есть только в заголовках письма, поэтому черновик со скрытой копией при отправке потерял бы получателей.
- Сборка письма оставляла скрытую копию только в конверте SMTP. Серверные интерфейсы принимают целый текст письма, и скрытая копия не доходила до получателя.
- Разбор адреса ядром принимает имя с запятой только в кавычках.

## Термины и состояния

- Черновик - письмо с флагом черновика или письмо, лежащее в папке с типом "Черновики". Некоторые транспорты флаг не ставят, поэтому папка тоже признаётся.
- Действия входящего - "Ответить", "Ответить всем", "Переслать", "В архив", "В спам", "Отложить", "Непрочитанное", "Отписаться", "Печать", "Создать правило", "Заблокировать отправителя", "Игнорировать переписку", "Автоочистка по отправителю" и быстрые действия.
- Действия черновика - "Отправить", "Удалить", флажок, сроки, закрепление, метка, "Исходный текст", "Сохранить как .eml", "Удалить навсегда".
- Показанное письмо - письмо, тема и тело которого стоят в области чтения.
- Снимок письма - получатели, тема, текстовая часть, тело и вложения черновика, прочитанные для отправки.

## Требования

### S-001. Признак черновика

WHEN у письма стоит флаг черновика или оно лежит в папке с типом "Черновики", система SHALL считать письмо черновиком.

### S-002. Панель над черновиком

WHILE в области чтения показан черновик, система SHALL показать в панели над письмом кнопку "Отправить".

Панель следует за показанным письмом. Контекстное меню списка делает активным письмо под курсором, не показывая его, но кнопки панели, кнопка "Отправить" и меню "Ещё" действуют на показанное письмо. Пока контекстное меню открыто, его пункты действуют на письмо под курсором; после закрытия меню показанное письмо снова активное. Над пустой областью чтения кнопки действий черновика нет.

### S-003. Действия входящего в панели

WHILE в области чтения показан черновик, система SHALL NOT показывать в панели над письмом действия входящего.

### S-004. Меню "Ещё"

WHILE в области чтения показан черновик, система SHALL оставить в меню "Ещё" только действия черновика и настройку панели.

### S-005. Отправка первым пунктом меню

WHEN контекстное меню открывается на черновике, система SHALL поставить "Отправить" первым пунктом.

### S-006. Действия входящего в контекстном меню

WHEN контекстное меню открывается на черновике, система SHALL NOT показывать в нём действия входящего.

### S-007. Открытое меню черновика

WHILE контекстное меню черновика открыто, система SHALL сохранять набор его пунктов при обновлении состава быстрых действий.

### S-008. Отправка черновика

WHEN пользователь нажимает "Отправить" на черновике, у которого есть получатель в поле "Кому" или "Копия", система SHALL передать в очередь отправки письмо с получателями, темой, текстовой частью, телом и вложениями черновика тем же путём, что письмо из редактора, включая окно отмены отправки.

Скрытая копия - не повод отправлять в один клик: на письме не видно ни одного адресата, поэтому такой черновик открывается в редакторе (S-011).

### S-009. Отправка без редактора

WHILE черновик отправляется одним нажатием, система SHALL NOT изменять содержимое редактора.

### S-010. Текстовая часть письма

WHEN черновик отправляется без правок, система SHALL передать его исходную текстовую часть, а не строить её из разметки.

У письма без собственной текстовой части (только разметка) текстовая часть уходит пустой.

### S-011. Черновик без получателя

IF у черновика нет получателя в поле "Кому" или "Копия", THEN система SHALL открыть редактор с содержимым черновика и подсказкой указать получателя.

### S-012. Отправка из редактора

WHEN письмо уходит в очередь из редактора, в который открыт черновик, система SHALL считать исходный черновик отправленным (S-014).

### S-013. Другое письмо в редакторе

IF в редакторе есть другое неотправленное письмо в момент, когда черновик нужно открыть в редакторе, THEN система SHALL оставить это письмо в редакторе нетронутым.

Черновик при этом не отправляется. То же письмо, что уже открыто из этого черновика, другим письмом не считается.

### S-014. Черновик после отправки

WHEN письмо принято в очередь отправки, в том числе с отправкой на выбранное время, система SHALL переместить исходный черновик из папки "Черновики" в корзину.

### S-015. Повторная отправка

WHILE программа работает, система SHALL NOT принимать повторную отправку черновика, письмо которого уже принято в очередь, даже если черновик остался в папке из-за пропуска перемещения.

### S-016. Повторное нажатие

WHILE черновик отправляется, система SHALL NOT начинать вторую отправку того же черновика.

### S-017. Кнопка после принятия

WHEN письмо черновика принято в очередь отправки, система SHALL убрать кнопку "Отправить" с панели сразу, не дожидаясь перемещения черновика в корзину.

Кнопка скрыта только над черновиками, чьи письма уже приняты в очередь в этом сеансе. Над следующим показанным черновиком, чьё письмо ещё не принято, кнопка есть.

### S-018. Другое письмо во время чтения

IF пользователь начинает другое письмо, пока черновик или его вложения читаются, THEN система SHALL оставить это письмо нетронутым.

### S-019. Ответ очереди

WHEN очередь отвечает на отправку или запланированную отправку из редактора, система SHALL очистить редактор только если в нём всё ещё отправленное письмо.

Письмо, начатое за время ожидания, остаётся нетронутым, а черновик отправленного письма всё равно убирается из папки. Пока запланированная отправка выполняется, второе нажатие её не запускает.

### S-020. Неполное тело

IF черновик хранится только в виде заголовков и превью, THEN система SHALL отказаться отправлять его, сообщить, что тело черновика не загружено, и не трогать его в папке.

### S-021. Вложения

WHEN черновик переносится в редактор или в очередь, система SHALL переносить обычные вложения вложениями, не добавляя второй раз части, встроенные в тело.

Вложением второй раз не становится только часть, которую ядро пометило как встроенную в тело. Ядро помечает часть, только когда заменило ссылку картинки в теле на данные части. Файл с идентификатором части, на который тело не ссылается картинкой, остаётся вложением.

### S-022. Предел размера при чтении

WHEN читается очередное вложение черновика, система SHALL остановить чтение, если следующий файл не помещается в предел письма.

Размер вложения, который ядро уже знает, проверяется до чтения его содержимого. Встроенные картинки тела считаются до вложений, поэтому письмо из одних картинок тоже проверяется.

### S-023. Предел размера в ядре

WHEN письмо со вложениями и встроенными картинками сверх предела размера предлагается в очередь, система SHALL отвергнуть его до записи в очередь.

### S-024. Имя со спецсимволами

WHEN имя получателя содержит запятую, кавычку или другой спецсимвол, система SHALL передать ядру его одним адресом с именем в кавычках.

### S-025. Адреса в автосохранении

WHEN редактор сохраняет письмо автоматически, система SHALL хранить адреса списком, чтобы имя не разбивалось после восстановления.

### S-026. Скрытая копия черновика

WHEN черновик открывается, система SHALL вернуть его скрытую копию из заголовков письма одинаково при первом чтении и при чтении из кэша разбора.

Черновик ядро узнаёт тем же признаком, что и интерфейс: флаг черновика или папка с типом "Черновики".

### S-027. Скрытая копия для серверного интерфейса

WHEN письмо со скрытой копией отправляется через интерфейс, принимающий целый текст письма (Gmail, EWS, JMAP), система SHALL оставить заголовок скрытой копии внутри письма.

### S-028. Скрытая копия для SMTP

WHEN письмо со скрытой копией отправляется через SMTP, система SHALL передать скрытую копию только в конверте.

### S-029. Тело письма в редакторе

WHEN тело письма попадает в редактор из черновика, из отменённой отправки или из автосохранения, система SHALL удалить из него скрипты, обработчики событий, стили письма и адреса внешних картинок, сохранив встроенные картинки и обычные ссылки.

Из тела удаляются также классы, идентификаторы и стили, которые могут перекрыть программу.

### S-030. Обычное письмо

WHERE открыто письмо, которое не является черновиком, система SHALL показать прежний набор действий без изменений.

### S-031. Отправитель при обновлении данных

WHEN список ящиков перестраивается при обновлении данных, система SHALL сохранить для письма в редакторе ящик, выбранный в поле "От кого".

### S-032. Отказ ядра по письму

WHEN ядро отвергает письмо черновика из-за адреса или размера, система SHALL открыть редактор с содержимым черновика и причиной отказа.

Черновик в папке при этом не трогается.

## Интерфейсы и данные

- `MessageFull` получает поле `bcc` (список адресов, по умолчанию пустой). Для черновика оно заполняется из заголовка Bcc при каждом чтении, в том числе когда разобранное письмо берётся из кэша; для остальных писем остаётся пустым. Для чтения разбираются только заголовки письма.
- `MessageFull` получает поле `body_fetched` (по умолчанию истина): ложь означает, что хранятся только заголовки и превью письма.
- `MessageFull` получает поле `has_text_part` (по умолчанию истина): ложь означает, что у письма нет своей текстовой части и текст построен из разметки.
- `Attachment` получает поле `embedded` (истина, когда ядро заменило ссылку картинки в теле на данные части). Результат разбора без пометок у частей ядро разбирает заново и сохраняет с пометками.
- Роль папки, признак полноты тела и ссылка на сохранённое письмо читаются одним запросом в `get_message` (`crates/core/src/storage/repo.rs`).
- Сборка письма имеет два вида: для SMTP (`build_message`, скрытая копия только в конверте) и для серверных интерфейсов (`build_message_with_bcc`, заголовок скрытой копии остаётся в письме). `validate_outgoing` проверяет и адреса, и предел размера вложений и встроенных картинок.
- Модуль `apps/desktop/ui/modules/draft-message.js` отвечает на два вопроса без обращения к документу и к ядру: является ли письмо черновиком (`isDraftMessage`) и какие действия к нему применимы (`actionsForMessage`, перечень `DRAFT_ACTIONS`).
- Панель над письмом получает кнопку "Отправить" (`#threadSendDraft`, действие `send-draft`), постоянную: настройка панели её не прячет, для обычного письма она скрыта.
- Интерфейс помнит письмо, показанное в области чтения (`paneLetter`), и черновики, письма которых уже приняты в очередь (`sentDrafts`, в пределах сеанса).
- При смене показанного письма панель перестраивается только тогда, когда письмо сменилось между черновиком и остальными (`refreshToolbarForMessage`), а видимость кнопки "Отправить" пересчитывается при каждой смене письма. Выбор письма контекстным меню списка панель не меняет.
- Контекстное меню списка помнит письмо, для которого оно открыто (`contextLetter`). Закрытие меню возвращает активным показанное письмо (`restoreActiveToShown`); обработчики панели вызывают ту же функцию до действия, потому что нажатие на кнопке доходит раньше, чем документ закрывает меню.
- Ящик, выбранный в поле "От кого", хранится отдельно от списка ящиков (`composerFromAccount`): список очищается и строится заново на каждом обновлении данных.
- `readDraftLetter` показывает в статусе редактора отказ ядра вместе с его причиной (`refusalText`).
- Отправку ведёт `sendDraftMessage` (`apps/desktop/ui/modules/composer.js`): читает письмо и вложения в снимок (`readDraftLetter`) и передаёт снимок в очередь (`queueLetter`); когда письмо нужно закончить, снимок переносится в редактор (`applyDraftToComposer`) без ожиданий между сбросом и заполнением.
- Схема базы данных не меняется.

## Ошибки и частичные отказы

- Если письмо не удалось прочитать, система показывает причину, ничего не отправляет и черновик не трогает.
- Если не удалось вложение или письмо не помещается в предел размера, редактор открывается с тем, что успело загрузиться, и с причиной; отправка из этого редактора тоже убирает черновик.
- Если редактор не принял письмо (нет получателя, неверный адрес), редактор остаётся заполненным черновиком, а черновик остаётся в папке.
- Если ядро отвергло письмо по адресу или размеру, редактор открывается заполненным черновиком с причиной отказа, а черновик остаётся в папке.
- Если ядро пропустило перемещение черновика в корзину (нет единственной папки корзины, письмо занято другой операцией), система сообщает причину пропуска и предлагает удалить черновик вручную. Черновик, уже лежащий в корзине, отказом не считается.
- Отправка, отменённая в окне отмены, возвращает письмо в редактор, как любое отменённое письмо. Серверный черновик к этому времени уже лежит в корзине.

## Одновременная работа, повторы и защита от дублей

- Повторное нажатие "Отправить" в редакторе опознаётся по ключу запроса и вторую отправку не создаёт (undo-send.md, S-053).
- Пока черновик отправлен, кнопка "Отправить" на панели скрыта: показанное письмо сброшено, а черновик с принятым письмом запомнен до конца сеанса.
- Запланированная отправка захватывает черновик редактора до обращения к ядру и очищает редактор только если поколение редактора не изменилось за время ответа.
- Связь "редактор - черновик" держится до первого сброса редактора: новое письмо, ответ или пересылка сбрасывают её, поэтому отправка другого письма чужой черновик не удаляет.
- Отправка одним нажатием не читает редактор и не пишет в него, поэтому файл из проводника, смена списка ящиков и другое письмо в редакторе на неё не влияют.

## Безопасность и конфиденциальность

- Содержимое черновика не покидает программу иначе, чем при отправке письма из редактора: те же проверки адресов, тот же предел размера, та же очередь.
- Вложения черновика проходят предел размера письма, как вложения, добавленные в редакторе.
- Тело письма попадает в редактор только после очистки (S-029): скрипты, обработчики событий, стили письма и внешние картинки в документ программы не попадают. Черновик разбирается в инертном дереве и переносится в документ после очистки.

## Совместимость, перенос данных и откат

Миграция 0056 добавляет в кэш разбора колонку признака собственной текстовой части и очищает кэш: сохранённые результаты разбора не несут пометок встроенных частей, поэтому письма разбираются заново при первом открытии. Откат возвращает единый перечень действий для всех писем; поля `bcc`, `body_fetched`, `has_text_part` и `embedded` в ответах команд интерфейс старой версии игнорирует.

## Скорость и потребление ресурсов

Панель перестраивается только при смене типа письма, а не при каждом открытии. Скрытая копия черновика читается из сохранённого письма при каждом открытии, причём разбираются только заголовки; для остальных писем дополнительных чтений нет. Предел размера проверяется по размеру вложения, который ядро уже знает, до чтения содержимого, а для прочитанного содержимого - по длине его данных, до разворачивания в памяти.

## Журналы, метрики и эксплуатация

- Отправка черновика пишет те же записи, что отправка из редактора: карточка окна отмены в журнале событий.
- Неудачное перемещение черновика в корзину пишет ошибку в журнал программы (запись интерфейса) и сообщение в строке статуса.

## Отклонённые варианты

- Убирать черновик только после истечения окна отмены. Черновик оставался бы в папке несколько секунд после нажатия "Отправить", и пользователь не понимал бы, ушло письмо или нет. Отменённая отправка и так возвращает письмо в редактор.
- Редактирование черновика с сохранением обратно в папку. Требует записи черновика в папку на сервере для каждого транспорта - это отдельная задача. Кнопка "Изменить" без сохранения обманывала бы пользователя, поэтому её нет.
- Отправлять черновик силами ядра из сохранённого письма. Очередь отправки собирает письмо из полей, а не из готового текста; изменение очереди задело бы окно отмены и повторы отправки.
- Отправлять черновик через скрытый редактор (первая реализация). Всё, что происходило с редактором во время чтения черновика, ломало отправку: другое письмо затиралось, список ящиков менял отправителя, файл из проводника попадал в письмо, тело письма шло в документ без очистки.
- Запоминать принятые черновики в ядре со ссылкой на операцию очереди. Защитило бы повтор после перезапуска, но требует решить, когда изменённый черновик можно отправлять заново.

## Открытые вопросы

- Правки черновика в редакторе не сохраняются в папку "Черновики": серверный черновик остаётся прежним, пока письмо не отправлено. Требует записи черновика на сервер (см. отклонённые варианты).
