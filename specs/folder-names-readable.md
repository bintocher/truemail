# Читаемые имена папок в настройках

- Состояние: реализована
- Задача: запрос пользователя от 2026-09-02 (issue не заводился)
- Обновлено: 2026-09-02
- Ревизия: 1

## Цель и результат для пользователя

В разделе настроек "Сквозные папки" имена папок нечитаемы:
у IMAP-аккаунта видно строки вида `&BB4EQgQ,BEAEMAQyBDsENQQ9BD0EswQ1-`, у Exchange -
длинные идентификаторы вида `AAMkADRkM2U1ZDAwLTBiYTQ...`. После правки там видно обычные
имена папок, как в панели слева. Список сопоставления папок правки не требует: он уже
берёт `display_name` (`settings.js:65`).

## Границы задачи

- Правка в `apps/desktop/ui/modules/settings.js` (подпись строки источника),
  `apps/desktop/ui/modules/mail.js` (порядок сортировки папок), новый модуль
  `apps/desktop/ui/modules/folder-names.js` с проверками, подключение и версия в
  `index.html`, маска запуска проверок в `Makefile` и `.github/workflows/ci.yml`.
- Ядро, схема базы и синхронизация не меняются: человекочитаемое имя уже приходит в
  `display_name`.

## Что не входит в задачу

- Исправление уже сохранённых записей базы: `display_name` перезаписывается при каждой
  синхронизации списка папок, отдельная миграция не нужна.
- Показ полного пути вложенной папки во всех остальных экранах интерфейса.
- Тесты на разбор папок EWS и JMAP (их нет и они не появляются в этой задаче).

## Текущее поведение и доказательства

- Подпись строки источника: `settings.js:75`,
  `row.querySelector('.source-path').textContent=folder.remote_path||folder.display_name`.
  Технический путь имеет приоритет над человекочитаемым именем, а он всегда непустой
  (`crates/core/src/model/folder.rs:99-107`), поэтому `display_name` не используется.
- `parent_id` заполняется только у Exchange (`ews.rs:1315-1324`); IMAP и JMAP всегда
  отдают пустого родителя (`imap.rs:996`, `jmap.rs:622`, `jmap.rs:448`), поэтому для
  IMAP иерархия читается из разделителей `remote_path` - именно так уже поступает
  `folderTreeRows` (`mail.js:118-129`).
- Что лежит в полях:
  - IMAP - `remote_path` это серверное имя в modified UTF-7, `display_name` -
    декодированный последний сегмент (`crates/core/src/backend/imap.rs:976-1003`,
    декодер `imap.rs:1964-1997`);
  - EWS - `remote_path` это `FolderId`, `display_name` это `DisplayName`
    (`crates/core/src/backend/ews.rs:1285-1323`);
  - JMAP - `remote_path` это `Mailbox.id`, `display_name` это `Mailbox.name`
    (`crates/core/src/backend/jmap.rs:608-629`).
- Данные в базе корректны: `save_discovered_folders` (`crates/core/src/storage/repo.rs:718-747`)
  обновляет `display_name` при каждой синхронизации списка папок
  (`crates/core/src/account/mod.rs:781-795`, `2058-2085`).
- Остальной интерфейс уже показывает читаемое имя через `folderTitle`
  (`mail.js:116`): панель папок (`mail.js:622`), заголовок списка (`mail.js:628`),
  правила (`smart-rules.js:194`, `210`), сообщение о переносе (`mail.js:266`).
  Сопоставление ролей в настройках берёт `display_name` (`settings.js:65`).
- Сортировка списка папок идёт по `remote_path` (`mail.js:117`), то есть для EWS по
  идентификатору, для IMAP по закодированному пути.
- `display_name` содержит только последний сегмент пути, поэтому две вложенные папки с
  одинаковым именем в разных ветках выглядят одинаково; связь с родителем есть в
  `parent_id` (`folder.rs:99-107`).

## Термины и состояния

- Техническое имя папки - `remote_path`: путь IMAP в modified UTF-7 либо непрозрачный
  идентификатор EWS или JMAP.
- Человекочитаемое имя - `display_name`: декодированное имя последнего сегмента.
- Путь для показа - цепочка человекочитаемых имён от корня к папке, соединённая
  разделителем `/`.

## Требования

### S-001. Список сквозных папок показывает человекочитаемое имя

Система SHALL показывать в строке списка источников (`settings.js:75`) путь для показа.

### S-002. Вложенные папки различимы

IF у папки заполнен `parent_id` и родитель есть в списке (так приходит Exchange), THEN система SHALL строить подпись строки списка источников как путь от корня по цепочке человекочитаемых имён.

Иерархия берётся из двух источников - по тому же принципу, что и в `folderTreeRows` (`mail.js:118-129`), но решение принимается для каждой папки отдельно, а не одним флагом на весь список, как там. Две одноимённые папки в разных ветках дают разные подписи.

### S-003. Порядок строк соответствует показанным именам

Система SHALL сортировать список источников по показанной подписи.

### S-004. Пустые и битые значения не ломают строку

IF `display_name` пуст, THEN система SHALL показывать в строке списка источников `remote_path`.

Fallback декодера modified UTF-7 (`imap.rs:985-994`) может вернуть сырое имя при повреждённых данных сервера - это допустимо и показывается как есть.

### S-005. Остальные экраны не меняются

Система SHALL NOT менять `folderTitle` и места, где он применяется.

Там уже показывается человекочитаемое имя и локализованное название роли.

### S-006. Без пути для показа берётся человекочитаемое имя

IF путь для показа построить нельзя, THEN система SHALL показывать в строке списка источников `display_name`.

### S-007. Без человекочитаемого имени берётся техническое

IF `display_name` пусто, THEN система SHALL показывать в строке списка источников `remote_path`.

### S-008. Техническое имя не вытесняет человекочитаемое

WHERE у папки есть человекочитаемое имя, система SHALL NOT показывать в строке списка источников техническое имя.

### S-009. Путь строится по разделителям технического имени

IF `parent_id` не даёт пути, а `remote_path` содержит разделители `/` или `|` (так устроен IMAP), THEN система SHALL строить подпись строки списка источников из сегментов `remote_path`, каждый из которых декодируется тем же способом, что и `display_name`.

### S-010. Без иерархии показывается имя самой папки

IF ни `parent_id`, ни разделители `remote_path` пути не дают (JMAP и плоские ящики), THEN система SHALL показывать в строке списка источников `display_name`.

Известные ограничения: у JMAP в `parent_id` приходит пустое значение (`crates/core/src/backend/jmap.rs:622`), а разделителей в идентификаторе нет, поэтому вложенность там не показывается. У IMAP-серверов с нестандартным разделителем иерархии (например, точкой) вложенность тоже не распознаётся: `remote_path` приходит как есть, без нормализации разделителя (`imap.rs:923-1003`). Это уже действующее поведение, задача его не меняет.

### S-011. Цепочка строится по загруженному списку папок

Система SHALL строить цепочку по уже загруженному списку папок аккаунта, без обращения к серверу.

### S-012. Отсутствующий родитель и цикл дают имя самой папки

IF родителя нет в списке папок или ссылка на родителя закольцована, THEN система SHALL брать только имя самой папки.

### S-013. Общая сортировка папок не меняется

Система SHALL NOT менять общую функцию `sortedFolders` (`mail.js:117`), которую используют ещё панель папок и список сопоставления.

### S-014. Сравнение применяется поверх порядка ролей

Система SHALL применять своё сравнение для списка источников поверх текущего порядка ролей (входящие, отправленные, черновики, архив, спам, корзина).

### S-015. Оба пустых значения дают пустую строку

IF `display_name` и `remote_path` пусты оба, THEN система SHALL показывать строку списка источников пустой строкой, а не значением `undefined`.

## Интерфейсы и данные

Новых команд, полей и миграций нет. Используются уже приходящие поля `Folder`:
`display_name`, `remote_path`, `parent_id`, `role`, `account_id`.

Чистые функции выносятся в `apps/desktop/ui/modules/folder-names.js`:

- `folderPathLabel(folder, foldersById)` -> строка подписи;
- `compareFolderLabels(a, b)` -> порядок строк списка источников по подписи;
- `decodeFolderSegment(segment)` -> человекочитаемый сегмент пути IMAP.

Декодера modified UTF-7 в интерфейсе сейчас нет (он есть только в ядре -
`imap.rs:1964-1997`), поэтому `decodeFolderSegment` пишется заново на JS. Его поведение
сверяется с тем же набором примеров, что и Rust-тесты (`imap.rs:2032-2145`): `INBOX`,
кириллические имена, экранирование `&`, повреждённая последовательность возвращается как
есть.

Проверки запускаются маской `node --test "apps/desktop/tests/js/*.test.js"` (Node
раскрывает её сам, проверено в bash и в pwsh на Node 24; результат обязан показывать
ненулевое число выполненных проверок). Цель
`test` в `Makefile` (обе ветки) и шаг в `.github/workflows/ci.yml` переводятся на эту
маску, иначе новые файлы проверок не выполняются - сейчас там жёстко указан один файл
(`Makefile:11`, `18`, `ci.yml:44-45`).

## Отклоненные варианты

- Показывать `folderTitle(folder)`: он подменяет имя локализованным названием роли, а
  роль и так показана отдельной меткой рядом - получился бы дубль.
- Декодировать `remote_path` всегда: для EWS и JMAP это идентификатор, а не путь, там
  декодировать нечего. Разделители разбираются только когда они есть (IMAP).
- Строить путь только по `parent_id`: он заполнен лишь у Exchange, то есть для
  IMAP-ящика из примера задача осталась бы нерешённой.
- Чинить записи в базе миграцией: `display_name` и так перезаписывается при каждой
  синхронизации списка папок.
