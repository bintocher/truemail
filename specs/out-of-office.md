# Автоответ "нет на месте"

- Состояние: утверждена
- Задача: issue #92
- Обновлено: 2026-09-18
- Ревизия: 3

## Цель и результат для пользователя

Автоответа в программе нет вовсе: ни в ядре, ни в интерфейсе, ни в миграциях, ни в спецификациях нет ни настройки отсутствия, ни отправки автоматического ответа, поэтому уехавший пользователь либо предупреждает корреспондентов вручную, либо настраивает автоответ в почтовом сервере через его собственный веб-интерфейс.

После изменения пользователь задаёт для ящика период отсутствия и два текста - один для своих, другой для внешних отправителей, - а программа отвечает на входящие письма этого периода один раз каждому адресату.

Для ящика Exchange настройка сохраняется на сервере, поэтому ответы уходят и при выключенном компьютере. Для остальных ящиков автоответ выполняет сама программа, и она прямо предупреждает, что ответы уходят только пока программа запущена и этот ящик синхронизируется. Вне сборки Windows ящик Exchange не работает вовсе, поэтому автоответ для него недоступен, и программа говорит об этом прямо, а не подменяет его локальным.

## Границы задачи

- Настройка отсутствия отдельно для каждого ящика: период, текст для своих и текст для внешних.
- Серверный автоответ для ящиков Exchange через операции чтения и записи настроек отсутствия.
- Отдельная ветка построения серверного модуля Exchange для операций отсутствия: общее построение модуля отдаёт обобщённый объект интерфейса почтового модуля.
- Локальный автоответ для ящиков Яндекс, Gmail, Outlook, обычного IMAP и JMAP как пятая стадия разбора нового письма.
- Определение внутреннего отправителя без Exchange по доменам ящиков и списку доменов пользователя.
- Правила молчания: рассылки, автоматические письма, служебные адреса, чужие письма и старая почта.
- Ограничение частоты ответов одному адресату и долговечная память об уже отправленных ответах.
- Постановка локального автоответа в очередь отправки с нулевым окном отмены.
- Дополнение облегчённых проекций письма заголовками, нужными правилам молчания, там, где это возможно без изменения общего интерфейса почтового модуля.
- Миграция `0047_out_of_office.sql`, применяемая после `0045_undo_send.sql`.
- Команды Tauri, раздел настроек ящика и маскирование новых значений в журнале и в диагностическом наборе.

## Что не входит в задачу

- Серверный автоответ Gmail, Яндекс, Mail.ru, iCloud, JMAP и обычного IMAP: у программы нет общего способа его задать.
- Любые другие серверные правила обработки почты.
- Ответы на письма, пришедшие при полностью закрытой программе в локальном режиме: их не будет, и это сказано пользователю прямо.
- Автоответ для ящика Exchange вне сборки Windows: такой ящик не синхронизируется вовсе.
- Обратная обработка почты, полученной до включения настройки.
- Несколько периодов отсутствия у одного ящика одновременно.
- Разные тексты для отдельных адресов или для отдельных внешних доменов.
- Вложения, оформление и подпись пользователя в автоответе.
- Расширение общего интерфейса почтового модуля операциями отсутствия: их поддерживает только Exchange, а остальные пять модулей получили бы пустые заглушки (`crates/core/src/backend/mod.rs:271`, `crates/core/src/backend/mod.rs:388`, `crates/core/src/backend/mod.rs:497`, `crates/core/src/backend/mod.rs:648`, `crates/core/src/backend/jmap.rs:620`).
- Точные правила защиты от циклов автоответов и от рассылок в серверном режиме: их определяет сервер Exchange по своей политике.
- Отметка минимальной совместимой версии базы: она вводится волной правил (`specs/mail-rules-conditions-and-actions.md`, S-079 и S-080) и здесь не заводится заново.

## Текущее поведение и доказательства

- Поиска по ядру, интерфейсу, миграциям и спецификациям достаточно, чтобы убедиться: отсутствия, автоответа и связанных с ними настроек в программе нет.
- Общий интерфейс почтового модуля описывает проверку, синхронизацию, операции, отправку, добавление копии и загрузку письма, но операций отсутствия не содержит (`crates/core/src/backend/mod.rs:176-252`).
- Этот интерфейс реализуют шесть модулей: Exchange (`crates/core/src/backend/ews.rs:3221`), JMAP (`crates/core/src/backend/jmap.rs:620`), Яндекс, Gmail, Outlook и обычный IMAP (`crates/core/src/backend/mod.rs:271`, `crates/core/src/backend/mod.rs:388`, `crates/core/src/backend/mod.rs:497`, `crates/core/src/backend/mod.rs:648`).
- Все запросы Exchange проходят через одну функцию и получают общий конверт (`crates/core/src/backend/ews.rs:610-639`, `crates/core/src/backend/ews.rs:247-255`).
- Конверт объявляет версию сервера `Exchange2010_SP2` (`crates/core/src/backend/ews.rs:251`).
- Значения запросов Exchange экранируются одной функцией на пять особых символов (`crates/core/src/backend/ews.rs:203-210`).
- Тела запросов Exchange уже собираются чистыми функциями, проверяемыми без сети (`crates/core/src/backend/ews.rs:219-230`, `crates/core/src/backend/ews.rs:236-245`).
- Запросы Exchange с проверкой подлинности NTLM и Negotiate выполняются только в сборке Windows; другая сборка возвращает явный отказ на любой запрос, потому что все запросы Exchange идут через одну и ту же функцию (`crates/core/src/backend/ews.rs:429-439`, `crates/core/src/backend/ews.rs:513-526`, `crates/core/src/backend/ews.rs:610-639`).
- Ядро строит серверный модуль ящика одной функцией и получает обобщённый объект интерфейса почтового модуля; ветка Exchange в ней отдельная (`crates/core/src/account/mod.rs:928-969`, `crates/core/src/account/mod.rs:957-968`).
- Ящик хранит вид серверного модуля и адрес службы Exchange (`crates/core/migrations/0001_accounts.sql:10`, `crates/core/migrations/0001_accounts.sql:19`), а перечисление видов различает Exchange и остальные (`crates/core/src/model/account.rs:5-23`).
- Адрес ящика объявлен уникальным (`crates/core/migrations/0001_accounts.sql:7`).
- Исходящее письмо собирается в MIME с проверкой адресатов и пределом вложений в 25 МБ (`crates/core/src/backend/smtp.rs:269-300`).
- Отправка выполняется через SMTP с пределом ожидания в 30 секунд (`crates/core/src/backend/smtp.rs:393`, `crates/core/src/backend/smtp.rs:466`) либо через интерфейс Gmail (`crates/core/src/backend/smtp.rs:406-427`).
- Очередь операций уже умеет хранить отправку с заданным сроком первой попытки (`crates/core/src/storage/repo.rs:3749-3765`) и выполняет её общим работником (`crates/core/src/account/mod.rs:1976-2068`).
- Новые письма обычной синхронизации сохраняются, после чего запускается разбор стадиями (`crates/core/src/account/mod.rs:1183-1185`, `crates/core/src/account/mod.rs:1189-1195`).
- В наблюдаемой синхронизации новые письма также сохраняются до разбора стадиями (`crates/core/src/account/mod.rs:2858-2866`, `crates/core/src/account/mod.rs:2877-2880`).
- Письма, догруженные прокруткой вглубь папки, сохраняются с отдельным признаком (`crates/core/src/account/mod.rs:1392-1394`).
- Признак рассылки уже вычисляется при разборе полного письма по заголовку `List-Unsubscribe` (`crates/core/src/storage/repo.rs:2969-2971`), там же разбираются ссылки отписки (`crates/core/src/storage/repo.rs:2972-2997`).
- Полное письмо IMAP загружается запросом, не устанавливающим признак прочтения (`crates/core/src/backend/imap.rs:74`, `crates/core/src/backend/imap.rs:1305-1308`).
- Облегчённая проекция Gmail сохраняет `List-Unsubscribe`, но не сохраняет `Auto-Submitted`, `Precedence`, `Return-Path` и `X-Auto-Response-Suppress` (`crates/core/src/backend/gmail_api.rs:833-848`).
- Облегчённый запрос Exchange перечисляет свойства письма поимённо и заголовков правил молчания не запрашивает (`crates/core/src/backend/ews.rs:1539-1555`, `crates/core/src/backend/ews.rs:798`), а локальное письмо собирается из этих свойств (`crates/core/src/backend/ews.rs:1604-1653`).
- Модуль JMAP скачивает сырое письмо целиком, поэтому его заголовки доступны разбору наравне с письмами IMAP (`crates/core/src/backend/jmap.rs:345-353`).
- Таблица настроек хранит общие пары ключа и значения и настроек по ящикам не предусматривает (`crates/core/migrations/0007_settings.sql:3-6`), а значения шифруются на уровне приложения (`crates/core/src/storage/mod.rs:236-256`).
- Подпись композера подставляется только в интерфейсе и к письмам, собранным ядром, отношения не имеет (`apps/desktop/ui/modules/composer.js:29`).
- Роли папок перечислены в ядре и назначаются в том числе угадыванием по имени (`crates/core/src/model/folder.rs:8-15`, `crates/core/src/model/folder.rs:42-73`).

## Термины и состояния

- Сквозной порядок стадий - списки отправителей, затем игнорируемые переписки, затем автоочистка по отправителю, затем правила обработки, затем локальный автоответ.
- Результат стадии - одно из состояний `passed`, `queued`, `failed_closed` и `failed_open`, как определено в `specs/mail-rules-conditions-and-actions.md`, S-008.
- Серверный режим - автоответ, хранимый на сервере Exchange его собственными операциями чтения и записи настроек отсутствия.
- Локальный режим - автоответ, который программа собирает и ставит в очередь отправки сама.
- Период отсутствия - промежуток от начала включительно до окончания не включительно.
- Внутренний домен - канонический домен из перечня доменов ящика: домен адреса самого ящика, домены других подключённых ящиков и домены, добавленные пользователем.
- Внутренний отправитель - отправитель, домен которого равен внутреннему домену или является его поддоменом.
- Внешний отправитель - допустимый отправитель, не признанный внутренним.
- Адрес назначения ответа - единственный адрес из заголовка `Reply-To`, а при его отсутствии - адрес отправителя письма.
- Ключ адресата - адрес назначения ответа, приведённый к ключу адреса по правилам `specs/blocked-senders.md`, S-009 и S-010: обрезанные внешние пробелы, нижний регистр и домен в общей международной форме.
- Запись ответа - долговечная запись о том, что ключу адресата уже отправлен автоответ этого ящика, с временем отправки.
- Окно молчания - семь суток от записи ответа, в течение которых тому же ключу адресата ответ не отправляется.
- Правило молчания - отдельное условие, при котором программа автоответ не создаёт.
- Кандидат на ответ - новое входящее письмо, прошедшее все правила молчания.
- Заголовок автоматического письма - `Auto-Submitted`, `Precedence`, `List-Unsubscribe`, `Return-Path` или `X-Auto-Response-Suppress` во входящем письме.

## Требования

### S-001. Настройка относится к одному ящику

WHERE пользователь открывает автоответ, программа SHALL показывать и сохранять настройку выбранного ящика отдельно от настроек остальных ящиков.

### S-002. Режим выбирает программа

WHEN программа открывает настройку автоответа, программа SHALL выбрать режим сама по виду серверного модуля ящика и по текущей сборке программы и SHALL NOT предлагать пользователю выбор между серверным и локальным режимом.

### S-003. Серверный режим для Exchange

IF ящик работает через серверный модуль Exchange и программа собрана для Windows, THEN программа SHALL использовать серверный режим.

### S-004. Exchange вне сборки Windows

IF ящик работает через серверный модуль Exchange, а программа собрана не для Windows, THEN программа SHALL сообщить, что автоответ для этого ящика недоступен, и SHALL NOT предлагать вместо него локальный автоответ, потому что вне сборки Windows все запросы Exchange отклоняются и ящик не синхронизируется вовсе.

### S-005. Локальный режим для остальных ящиков

IF ящик работает через любой серверный модуль, кроме Exchange, - Яндекс, Gmail, Outlook, обычный IMAP или JMAP, THEN программа SHALL использовать локальный режим.

### S-006. Режимы взаимно исключены

WHILE для ящика действует серверный режим, программа SHALL NOT создавать для него локальные автоответы, потому что иначе отправитель получил бы два ответа на одно письмо.

### S-007. Объяснение серверного режима

WHILE выбран серверный режим, программа SHALL сообщать, что автоответ хранится на сервере и работает при закрытой программе.

### S-008. Честное предупреждение локального режима

WHILE выбран локальный режим, программа SHALL сообщать, что ответы уходят только пока программа запущена и этот ящик синхронизируется.

### S-009. Операции отсутствия только в модуле Exchange

WHEN программа обращается к серверным настройкам отсутствия, программа SHALL выполнять это в серверном модуле Exchange и SHALL NOT добавлять операции отсутствия в общий интерфейс почтового модуля.

### S-010. Отдельная ветка построения модуля Exchange

WHEN ядру нужны операции отсутствия, программа SHALL построить серверный модуль Exchange отдельной ветвью с его адресом службы, именем пользователя и сроками ожидания, потому что общее построение модуля возвращает обобщённый объект интерфейса почтового модуля, у которого операций отсутствия нет.

### S-011. Чтение серверного состояния

WHEN пользователь открывает настройку ящика в серверном режиме, программа SHALL прочитать действующее состояние отсутствия с сервера и показать значения сервера, а не сохранённые локально.

### S-012. Запись серверного состояния

WHEN пользователь сохраняет включённый автоответ в серверном режиме, программа SHALL записать на сервер состояние с заданным периодом.

### S-013. Период в едином времени

WHEN программа передаёт период отсутствия серверу, программа SHALL передавать начало и окончание во всемирном времени.

### S-014. Два текста на сервере

WHEN программа записывает настройку отсутствия на сервер, программа SHALL передать текст для внутренних отправителей и текст для внешних отправителей отдельными значениями.

### S-015. Внешняя аудитория сервера

WHEN программа включает серверный автоответ, программа SHALL указать серверу, что внешний текст отправляется всем внешним отправителям, а не только известным.

### S-016. Проверка записи чтением

WHEN запись настройки отсутствия завершилась без ошибки передачи, программа SHALL перечитать состояние с сервера и показать только подтверждённые сервером значения.

### S-017. Отключение на сервере

WHEN пользователь отключает автоответ в серверном режиме, программа SHALL записать на сервер выключенное состояние.

### S-018. Отказ записи не меняет показанное состояние

IF запись настройки отсутствия на сервер не удалась, THEN программа SHALL сообщить об отказе, SHALL показывать последнее подтверждённое сервером состояние без изменений и SHALL NOT включать вместо него локальный автоответ, потому что отказ записи не выключает автоответ, уже включённый на сервере.

### S-019. Экранирование значений запроса

WHEN программа собирает запрос настроек отсутствия, программа SHALL пропустить период, тексты и адрес ящика через ту же функцию экранирования, что и остальные запросы Exchange.

### S-020. Разделение ответственности серверного режима

WHILE выбран серверный режим, программа SHALL сообщать, что защиту от рассылок, частоту ответов и деление отправителей на внутренних и внешних определяет сервер.

### S-021. Период локального режима

WHEN пользователь сохраняет локальный автоответ, программа SHALL требовать окончание периода позже его начала не менее чем на 1 минуту и не более чем на 366 суток.

### S-022. Граница окончания периода

WHEN время получения письма равно окончанию периода, программа SHALL считать период завершённым и автоответ не создавать.

### S-023. Предел длины текста

WHEN пользователь сохраняет текст автоответа, программа SHALL требовать от 1 до 10000 символов после обрезки внешних пробелов.

### S-024. Текст без оформления

WHEN программа сохраняет тексты автоответа, программа SHALL хранить их как обычный текст без разметки.

### S-025. Домены ящиков по умолчанию

WHEN локальная настройка ящика создаётся впервые, программа SHALL включить в перечень внутренних доменов домен адреса этого ящика и канонические домены адресов остальных подключённых ящиков; IF таких доменов больше 20, THEN программа SHALL оставить домен самого ящика и первые следующие по алфавиту домены до предела в 20 значений и сообщить пользователю, что остальные домены в перечень не вошли.

### S-026. Изменяемый перечень доменов

WHERE пользователь редактирует локальный режим, программа SHALL разрешать от 1 до 20 внутренних доменов.

### S-027. Каноническая форма домена

WHEN программа принимает внутренний домен, программа SHALL обрезать внешние пробелы, удалить ведущий знак `@` и завершающую точку, привести остаток к нижнему регистру и к общей международной форме по правилам `specs/blocked-senders.md`, S-009 и S-010.

### S-028. Внутренний отправитель

IF домен адреса назначения ответа равен внутреннему домену или оканчивается на точку и этот внутренний домен, THEN программа SHALL выбрать текст для внутренних отправителей.

### S-029. Внешний отправитель

IF домен адреса назначения ответа не признан внутренним, THEN программа SHALL выбрать текст для внешних отправителей.

### S-030. Место автоответа в сквозном порядке стадий

WHEN программа разбирает новое письмо, программа SHALL выполнять локальный автоответ пятой стадией, после списков отправителей, игнорируемых переписок, автоочистки по отправителю и правил обработки.

### S-031. Молчание при уводе письма предшествующей стадией

IF письмо закрыто предшествующей стадией результатом `queued` или `failed_closed`, THEN программа SHALL NOT создавать для него автоответ.

### S-032. Молчание вне папки входящих

IF письмо сохранено не в папке с ролью `inbox`, THEN программа SHALL NOT создавать для него автоответ.

### S-033. Молчание для догруженных писем

IF письмо сохранено с признаком догрузки прокруткой вглубь папки, THEN программа SHALL NOT создавать для него автоответ.

### S-034. Молчание вне периода отсутствия

IF время получения письма меньше начала периода или не меньше его окончания, THEN программа SHALL NOT создавать для него автоответ.

### S-035. Молчание для старого письма

IF время получения письма старше текущего времени более чем на 24 часа, THEN программа SHALL NOT создавать для него автоответ.

### S-036. Адрес назначения ответа

WHEN программа проверяет правила молчания и окно молчания, программа SHALL брать один адрес назначения ответа - адрес из заголовка `Reply-To`, а при его отсутствии адрес отправителя - и SHALL строить ключ адресата по этому адресу, чтобы проверка и отправка пользовались одним ключом.

### S-037. Несколько адресов для ответа

IF заголовок `Reply-To` содержит больше одного адреса, THEN программа SHALL NOT создавать автоответ, потому что ответ нескольким лицам раскрыл бы отсутствие тем, кто письма не писал.

### S-038. Молчание при рассылке

IF письмо содержит заголовок `List-Unsubscribe`, THEN программа SHALL NOT создавать для него автоответ.

### S-039. Недоступный заголовок правила молчания

WHERE серверный модуль ящика не сохраняет заголовок правила молчания и запросить его нельзя без изменения общего интерфейса почтового модуля, программа SHALL считать это правило молчания для такого ящика неприменимым, SHALL применять остальные правила молчания и SHALL сказать об этом в разделе автоответа ящика прямо.

### S-040. Молчание при автоматическом письме

IF письмо содержит заголовок `Auto-Submitted` со значением, отличным от `no` без учёта регистра и внешних пробелов, THEN программа SHALL NOT создавать для него автоответ.

### S-041. Молчание при массовой почте

IF письмо содержит заголовок `Precedence` со значением `bulk`, `list` или `junk` без учёта регистра, THEN программа SHALL NOT создавать для него автоответ.

### S-042. Молчание при пустом обратном адресе

IF письмо содержит заголовок `Return-Path` с пустым адресом, THEN программа SHALL NOT создавать для него автоответ.

### S-043. Молчание по запрету отправителя

IF письмо содержит заголовок `X-Auto-Response-Suppress` со значением, содержащим `All` или `OOF` без учёта регистра, THEN программа SHALL NOT создавать для него автоответ.

### S-044. Молчание для служебных адресов

IF локальная часть адреса отправителя или локальная часть адреса назначения ответа без учёта регистра равна `mailer-daemon`, `postmaster`, `no-reply` или `noreply`, THEN программа SHALL NOT создавать для этого письма автоответ.

### S-045. Молчание при собственном адресе

IF адрес отправителя или адрес назначения ответа совпадает с адресом любого подключённого ящика, THEN программа SHALL NOT создавать для этого письма автоответ.

### S-046. Молчание для чужой переписки

IF адрес ящика отсутствует и в поле "Кому", и в поле "Копия" письма, THEN программа SHALL NOT создавать для него автоответ, потому что письмо получено по скрытой копии или через список рассылки.

### S-047. Молчание при неразобранном отправителе

IF письмо не содержит ровно одного разобранного адреса отправителя, THEN программа SHALL NOT создавать для него автоответ.

### S-048. Молчание внутри окна молчания

IF ключу адресата уже отправлен автоответ этого ящика и с его времени прошло меньше семи суток, THEN программа SHALL NOT создавать следующий автоответ.

### S-049. Молчание при нераспознанном значении заголовка

IF значение заголовка автоматического письма присутствует, но не поддаётся разбору - `Auto-Submitted` без ключевого слова, `Return-Path` без разборного адреса, `X-Auto-Response-Suppress` без перечня значений или значение любого из этих заголовков, повторённое в письме дважды с разным смыслом, - THEN программа SHALL NOT создавать автоответ, потому что молчание безопаснее ответа рассылке; значение заголовка `Precedence` вне перечня `bulk`, `list` и `junk` нераспознанным не считается и молчания не вызывает.

### S-050. Срок памяти о записях ответов

WHEN записи ответа исполняется 60 суток, программа SHALL разрешить её удаление фоновым обслуживанием.

### S-051. Новое включение очищает память

WHEN пользователь включает автоответ ящика заново, программа SHALL удалить прежние записи ответов этого ящика, чтобы новый период отсутствия начинался без унаследованного молчания.

### S-052. Неделимая постановка ответа

WHEN письмо признано кандидатом на ответ, программа SHALL одной неделимой операцией проверить окно молчания по ключу адресата, записать запись ответа и поставить отправку в очередь.

### S-053. Повтор обработки того же письма

WHEN программа повторно разбирает то же входящее письмо, программа SHALL использовать уже созданную запись ответа и SHALL NOT ставить вторую отправку.

### S-054. Ответ уходит через очередь отправки

WHEN программа создаёт локальный автоответ, программа SHALL поставить его в очередь отправки с происхождением `automatic` и нулевым окном отмены по правилам `specs/undo-send.md`, S-057.

### S-055. Один адресат ответа

WHEN программа собирает автоответ, программа SHALL адресовать его ровно одному адресату - адресу назначения ответа по S-036 - и SHALL NOT заполнять поля "Копия" и "Скрытая копия".

### S-056. Признак автоматического ответа

WHEN программа собирает автоответ, программа SHALL добавить заголовок `Auto-Submitted` со значением `auto-replied`.

### S-057. Запрет ответов на автоответ

WHEN программа собирает автоответ, программа SHALL добавить заголовок `X-Auto-Response-Suppress` со значением `All`.

### S-058. Связь с исходным письмом

WHEN программа собирает автоответ, программа SHALL заполнить заголовки `In-Reply-To` и `References` идентификатором исходного письма, если он разобран.

### S-059. Тема ответа

WHEN исходная тема непуста, программа SHALL составить тему ответа из `Re: ` и исходной темы и SHALL NOT добавлять `Re: ` второй раз, если исходная тема уже начинается с него.

### S-060. Тема при пустой исходной теме

IF исходная тема пуста, THEN программа SHALL использовать тему "Автоответ".

### S-061. Ответ без подписи

WHEN программа собирает автоответ, программа SHALL отправить только сохранённый текст отсутствия и SHALL NOT добавлять подпись композера, исходное тело, вложения и оформление.

### S-062. Проверка кандидата без загрузки тела

WHEN программа проверяет правила молчания, программа SHALL пользоваться сохранёнными полями письма и его заголовками и SHALL NOT загружать тело письма из сети.

### S-063. Заголовки в облегчённых проекциях

WHEN серверный модуль сохраняет облегчённую проекцию нового письма, программа SHALL включить в неё заголовки `Auto-Submitted`, `Precedence`, `Return-Path` и `X-Auto-Response-Suppress` дополнительно к уже сохраняемому `List-Unsubscribe`, если это возможно без изменения общего интерфейса почтового модуля.

### S-064. Ответы после запуска программы

WHEN программа запускается и находит новые письма периода отсутствия, по которым записи ответа ещё нет, программа SHALL ответить только на письма не старше 24 часов по S-035.

### S-065. Число писем без ответа

WHEN программа при запуске пропускает письма периода отсутствия старше 24 часов, программа SHALL показать их число отдельным сообщением в разделе автоответа ящика.

### S-066. Ответ, поставленный до окончания периода

IF автоответ поставлен в очередь до окончания периода отсутствия, THEN программа SHALL довести его обычные безопасные повторы до конца и после окончания периода.

### S-067. Отключение локального автоответа

WHEN пользователь отключает локальный автоответ, программа SHALL отменить его ещё не начатые отправки этого ящика.

### S-068. Уже начатый ответ при отключении

IF автоответ уже передаётся серверу, THEN программа SHALL показать его итог отдельно от итога отключения настройки и SHALL NOT обещать его отмену.

### S-069. Удаление ящика с серверным автоответом

WHEN пользователь удаляет ящик с включённым серверным автоответом, программа SHALL предупредить, что автоответ остаётся включённым на сервере, и показать его серверное состояние до подтверждения удаления; IF состояние прочитать не удалось, THEN программа SHALL показать последнее подтверждённое сервером состояние вместе со временем его чтения и предупредить, что сейчас сверить его с сервером нельзя.

### S-070. Удаление ящика с локальным автоответом

WHEN пользователь удаляет ящик, программа SHALL удалить каскадом его локальную настройку отсутствия, записи ответов и ещё не начатые автоответы.

### S-071. Смена языка интерфейса

WHEN пользователь меняет язык интерфейса, программа SHALL показать подписи раздела автоответа на новом языке без перезапуска программы; тексты отсутствия, введённые пользователем, SHALL остаться без изменений.

### S-072. Маскирование в журнале и диагностике

WHEN программа пишет сведения об автоответе в журнал или в диагностический набор, программа SHALL маскировать адрес отправителя, адрес назначения ответа, внутренние домены и оба текста отсутствия.

## Интерфейсы и данные

- Миграция `0047_out_of_office.sql` применяется после `0045_undo_send.sql` и опирается на отметку минимальной совместимой версии базы, записанную волной правил.
- Таблица настройки отсутствия хранит ссылку на ящик, признак включения, начало и окончание периода, текст для внутренних отправителей, текст для внешних отправителей, перечень внутренних доменов и номер версии настройки; ключ таблицы - ящик.
- Таблица записей ответов хранит ссылку на ящик, ключ адресата, идентификатор исходного письма, номер операции отправки, состояние и время ответа.
- Уникальный ключ записей ответов один: пара ящика и идентификатора исходного письма. Окна молчания в ключе нет: частичное ограничение схемы не может зависеть от текущего времени, а после истечения окна тому же ключу адресата нужна новая запись.
- Окно молчания проверяется запросом по паре ящика и ключа адресата внутри той же неделимой операции, что и вставка записи ответа; этот запрос обслуживает отдельный индекс по ящику, ключу адресата и времени ответа.
- Обе таблицы ссылаются на ящик с каскадным удалением.
- Таблица писем дополняется полями признака рассылки, значения `Auto-Submitted`, значения `Precedence`, признака пустого обратного адреса и значения `X-Auto-Response-Suppress`; для IMAP они извлекаются из полного письма при сохранении.
- Перечень заголовков облегчённой проекции Gmail дополняется четырьмя заголовками по S-063.
- Признак рассылки и остальные заголовки правил молчания доступны не во всех серверных модулях: письма IMAP и JMAP разбираются из сырого письма целиком, проекция Gmail расширяется перечнем заголовков, а облегчённый запрос Exchange расширенными свойствами заголовков; там, где заголовок получить нельзя, соответствующее правило молчания не применяется по S-039.
- Облегчённый запрос Exchange дополняется расширенными свойствами заголовков письма, чтобы локальная модель письма была полной; серверный автоответ Exchange от этого разбора не зависит.
- Серверный модуль Exchange получает собственные операции чтения и записи настроек отсутствия, построенные на действующей функции запроса, конверте `Exchange2010_SP2` и функции экранирования; общий интерфейс почтового модуля не меняется.
- Ядро строит модуль Exchange для этих операций отдельной ветвью и работает с ним как с модулем Exchange, а не как с обобщённым объектом интерфейса почтового модуля.
- Для ящика Exchange период и тексты являются серверными данными: локальная база хранит последнее подтверждённое сервером состояние, время его чтения и вид последней ошибки; показывается всегда последнее подтверждённое состояние.
- Для остальных ящиков период, тексты и домены хранятся в зашифрованной базе.
- Добавляются команды чтения настройки отсутствия, её сохранения, отключения и перечисления последних ответов ящика.
- Команды объявляются в `commands.rs`, регистрируются в `main.rs`, открываются через `bridge.js` и перечисляются в проверке контракта команд явно.
- Автоответ ставится в очередь отправки с ключом запроса, построенным из ящика и локального номера входящего письма, поэтому повторный разбор того же письма не создаёт вторую отправку.
- Сообщения об ошибках выдаются по общим правилам `specs/error-kinds-and-messages.md`, подписи подчиняются `specs/ui-language-switch.md`.

## Ошибки и частичные отказы

- Отказ чтения серверного состояния показывается прямо и не подменяется ранее сохранённым локально значением.
- Отказ записи серверного состояния не включает локальный режим и не меняет показанное состояние: пользователь видит последнее подтверждённое сервером значение по S-018.
- Потерянный ответ на запись серверного состояния разрешается перечитыванием состояния до объявления успеха.
- Если запись ответа и постановка отправки не завершились вместе, обе записи откатываются, и письмо остаётся кандидатом следующего прохода.
- Временный отказ передачи автоответа обрабатывается общей очередью отправки с её повторами и пределом попыток.
- Неопределённый итог передачи автоответа не повторяется сам по правилам `specs/undo-send.md`, S-050.
- Окончательный отказ отправки показывается в разделе автоответа выбранного ящика с причиной.
- Отказ по одному письму не останавливает проверку остальных новых писем этого прохода.
- Ящик, у которого настройка отсутствия ссылается на удалённый или переименованный домен пользователя, продолжает отвечать внешним текстом и показывает предупреждение в разделе автоответа.
- Отсутствие сети при удалении ящика с серверным автоответом не прячет предупреждение: показывается последнее подтверждённое состояние и время его чтения по S-069.

## Одновременная работа, повторы и защита от дублей

- Одно входящее письмо создаёт не более одного автоответа: это защищено единственным уникальным ключом - парой ящика и идентификатора исходного письма.
- Запись ответа и постановка отправки выполняются одним писателем базы в одной неделимой операции.
- Два одновременных прохода синхронизации сходятся на уникальном ключе входящего письма, и второй проход отправку не создаёт.
- Окно молчания в семь суток проверяется запросом внутри той же неделимой операции, что и вставка записи ответа, потому что зависящее от текущего времени ограничение схемы невыразимо.
- Повтор операции отправки сохраняет ключ запроса и закреплённый идентификатор письма.
- Успешная передача переводит запись ответа в состояние отправленного ответа и записывает точное время.
- Отключение автоответа отменяет только ещё не начатые отправки, а уже начатая доводится до итога.
- Серверный режим не создаёт локальных записей ответов и не смешивается с локальным учётом частоты.
- Изменение текста отсутствия во время периода не сбрасывает уже начатые окна молчания.

## Безопасность и конфиденциальность

- Тексты отсутствия, перечень внутренних доменов и записи ответов относятся к конкретному ящику и хранятся только в зашифрованной базе.
- Запрос настроек отсутствия уходит только на уже настроенный адрес службы Exchange этого ящика и только по действующей схеме проверки подлинности.
- Все значения, попадающие в запрос Exchange, проходят через общую функцию экранирования.
- Проверка внутреннего отправителя выполняется только по локальным данным и не обращается к внешним службам.
- Автоответ не содержит исходного тела, вложений, перечня получателей и скрытых копий, поэтому не раскрывает переписку третьему лицу.
- Деление на внутренних и внешних выполняется по адресу отправителя, а не по отображаемому имени.
- Заголовок автоматического ответа предотвращает цикл с программами, соблюдающими этот стандарт, а окно молчания в семь суток ограничивает цикл с программами, которые его не соблюдают.
- Правило молчания для писем без адреса ящика в полях "Кому" и "Копия" не даёт отвечать на переписку, попавшую в ящик через рассылку или скрытую копию.

## Совместимость, перенос данных и откат

- Миграция применяется после миграции очереди отправки, потому что автоответ пользуется её состояниями и происхождением отправки.
- Письма, сохранённые до обновления, получают пустые значения новых полей заголовков и задним числом не разбираются.
- Настройка автоответа в прежних версиях отсутствовала, поэтому переносить нечего.
- Серверная настройка Exchange остаётся на сервере после удаления программы или локальной базы; на это пользователь предупреждается по S-069.
- Возврат на версию без этой миграции обычным путём не выполняется: программа отказывается открыть базу с отметкой минимальной совместимой версии новее себя самой и объясняет это пользователю (`specs/mail-rules-conditions-and-actions.md`, S-079 и S-080), а понижение схемы выполняется отдельной командой обслуживания.
- После такого понижения новые таблицы остаются неиспользуемыми, серверная настройка Exchange не меняется, а локальные ответы перестают уходить.
- Удаление новых таблиц требует подтверждения, потому что вместе с ними теряется память об уже отправленных ответах и первый же проход после этого ответит адресатам второй раз.
- Дополнение облегчённых проекций заголовками действует только для писем, полученных после обновления, и только в тех модулях, где эти заголовки доступны.

## Скорость и потребление ресурсов

- Проверка правил молчания использует поля строки письма и один индексированный запрос к записям ответов.
- Тело и вложения входящего письма при проверке не загружаются.
- На одно письмо-кандидата выполняется не более одного чтения записей ответов и одна неделимая запись.
- Записи ответов старше 60 суток удаляются пачками не более 500 строк.
- Облегчённые проекции прирастают не более чем на четыре коротких заголовка на письмо.
- Перечень внутренних доменов ограничен 20 значениями и сравнивается в памяти.
- Серверное состояние Exchange читается при открытии раздела, после сохранения и по явному обновлению, но не на каждом проходе синхронизации.
- Проверка пачки из 10000 новых писем измеряется без сетевых обращений и без загрузки тел.

## Отклонённые варианты

- Выполнять автоответ Exchange локально. Он перестал бы работать при выключенном компьютере, хотя сервер умеет это сам.
- Обещать локальный автоответ ящику Exchange вне сборки Windows. Такой ящик не синхронизируется вовсе, и обещание было бы ложным.
- Позволить пользователю выбрать локальный режим при доступном серверном. Такой выбор означает молчание при выключенном компьютере, и пользователь узнал бы об этом уже после отпуска.
- Молча включать локальный режим при отказе сервера. Пользователь получил бы другое время работы автоответа, не зная об этом.
- Включать оба режима одновременно. Отправитель получил бы два ответа на одно письмо.
- Добавить операции отсутствия в общий интерфейс почтового модуля. Их поддерживает только Exchange, а остальные четыре модуля получили бы пустые заглушки.
- Считать внутренними все адреса из адресной книги. Адресная книга не определяет организационную принадлежность.
- Сравнивать домен окончанием строки без точки. Тогда внутренний домен `example.com` молча захватил бы независимый домен `notexample.com`.
- Отвечать на все письма, найденные при запуске после долгого перерыва. Программа разослала бы запоздалые ответы на письма недельной давности.
- Ограничиться одним заголовком `Auto-Submitted`. Рассылки часто помечены только `Precedence` или только `List-Unsubscribe`.
- Отвечать на письмо, в котором адреса ящика нет ни в поле "Кому", ни в поле "Копия". Это переписка, попавшая в ящик через рассылку или скрытую копию, и ответ на неё раскрыл бы отсутствие постороннему.
- Хранить память об ответах только в оперативной памяти. Перезапуск снял бы ограничение частоты и вернул бы риск цикла между двумя автоответчиками.
- Отправлять автоответ напрямую, минуя очередь отправки. Временный сетевой отказ потерял бы ответ, а повторный разбор письма создал бы второй.
- Добавлять к автоответу подпись пользователя. Подпись раскрывает лишние сведения и не относится к короткому служебному сообщению.
- Хранить настройку отсутствия в общей таблице настроек. Она хранит общие пары ключа и значения, а настройка относится к конкретному ящику и должна удаляться вместе с ним.
- Выражать окно молчания уникальным ключом схемы по паре ящика и ключа адресата. Частичное ограничение не может зависеть от текущего времени, а после истечения окна тому же адресату нужна новая запись.
- Считать правила молчания по адресу отправителя, а отвечать на адрес для ответов. Проверка и отправка разошлись бы, и один и тот же адресат получал бы ответы чаще окна молчания.

## Открытые вопросы

- Нужна ли поддержка серверного значения "только известным отправителям" для внешней аудитории Exchange.
- Нужно ли показывать предварительный просмотр серверного оформленного текста, который Exchange может вернуть при чтении уже существующей настройки.
- Нужно ли позднее разрешить разные тексты для нескольких групп внутренних доменов.

## История решений

- Ревизия 2: уникальным остался только ключ пары ящика и исходного письма, а окно молчания переведено на запрос внутри той же неделимой операции, потому что ограничение схемы не может зависеть от текущего времени.
- Ревизия 2: записано, что признак рассылки и другие заголовки правил молчания доступны не во всех серверных модулях; для ящика, где заголовок недоступен, правило молчания не применяется и об этом сказано пользователю; модуль JMAP назван наравне с остальными.
- Ревизия 2: автоответ для ящика Exchange вне сборки Windows объявлен недоступным, потому что там отклоняется любой запрос Exchange и ящик не синхронизируется вовсе.
- Ревизия 2: в границы задачи внесена отдельная ветка построения серверного модуля Exchange для операций отсутствия.
- Ревизия 2: правила молчания и окно молчания сведены к одному ключу - адресу назначения ответа; письмо с несколькими адресами в `Reply-To` остаётся без ответа.
- Ревизия 2: отказ записи серверного состояния перестал менять показанное состояние: показывается последнее подтверждённое сервером значение.
- Ревизия 2: перечислено, что считается нераспознанным значением заголовка, и записано, что значение `Precedence` вне перечня нераспознанным не считается.
- Ревизия 2: требование об ответах после запуска переформулировано через новые письма, ещё не прошедшие стадию автоответа, вместо непроверяемых непрочитанных.
- Ревизия 2: описан случай отсутствия сети при удалении ящика с серверным автоответом.
- Ревизия 2: при числе подключённых ящиков больше двадцати перечень внутренних доменов по умолчанию обрезается до предела с сообщением пользователю.
- Ревизия 2: в откат добавлены отказ открыть базу с отметкой новее программы и понижение схемы отдельной командой обслуживания.
- Ревизия 2: число реализаций серверного модуля названо верно - их шесть; ссылки на код и на требования `specs/undo-send.md` исправлены.
- Ревизия 3: номер миграции сдвинут с `0046_out_of_office.sql` на `0047_out_of_office.sql`, потому что номер занял снимок кандидатов уборки из задач стадий; миграция ни разу не выпускалась, поэтому переименование безопасно.
