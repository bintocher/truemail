# Облегчённая выборка писем Exchange без полного сырого письма

- Состояние: реализована
- Задача: issue #23
- Обновлено: 2026-09-05
- Ревизия: 1

## Цель и результат для пользователя

Список писем ящика Exchange собирается дорогим способом: для каждого письма запрашивается полный набор свойств вместе с сырым письмом целиком, то есть вместе со всеми вложениями. Из-за этого обычная синхронизация и догрузка при прокрутке тянут десятки мегабайт ради строк списка, в которых видны только отправитель, тема, дата и отрывок текста. Догрузку пришлось резать порциями по 25 писем, и она всё равно ощущается медленной.

После изменения для списка запрашиваются только нужные свойства и текст письма, а сырое письмо целиком скачивается тогда, когда оно действительно нужно: при открытии письма или фоновой догрузкой тел. Список появляется быстрее, а вложения перестают скачиваться до того, как пользователь открыл письмо.

## Границы задачи

- Транспорт Exchange: `crates/core/src/backend/ews.rs` - выборка писем по идентификаторам (`messages_by_ids`), свежие письма папки (`recent_messages_in_folder`), письма старше даты (`older_messages_in_folder`), разбор ответа (`parse_messages`).
- Сборка минимального сырого письма из свойств, по образцу такой же сборки для Gmail (`crates/core/src/backend/gmail_api.rs`).
- Проверки: модульные проверки разбора ответов Exchange в `crates/core`.

## Что не входит в задачу

- Переход на выборку свойств через `FindItem` вместо `GetItem`: `FindItem` не возвращает почтовый адрес отправителя.
- Свойство "отрывок текста" (`item:Preview`): оно требует Exchange 2013, а программа объявляет серверу версию Exchange 2010 SP2.
- Догрузка вложений отдельными частями.
- Транспорты IMAP, Gmail и JMAP.
- Фоновая догрузка тел писем: она описана отдельной спецификацией и здесь только используется.

## Текущее поведение и доказательства

- `messages_by_ids` (`crates/core/src/backend/ews.rs:608`) отправляет `GetItem` с `BaseShape=AllProperties` и `IncludeMimeContent=true` (621), то есть получает сырое письмо целиком вместе с вложениями.
- Через эту же функцию идут все выборки писем: свежие письма папки (`recent_messages_in_folder`, 658), письма старше даты для догрузки при прокрутке (`older_messages_in_folder`, 686) и изменённые письма при инкрементальной синхронизации (757 и 854).
- `parse_messages` (`ews.rs:1356`) разбирает ответ, ожидая сырое письмо, и выдаёт письма с признаком `body_fetched: true` (`ews.rs:1386`).
- Открытие письма без тела уже поддержано: `fetch_message_raw` для Exchange (`ews.rs:3060`) запрашивает `GetItem` с `IncludeMimeContent=true` по одному письму (891).
- Конверт запроса объявляет версию сервера `Exchange2010_SP2` (`ews.rs:133`), поэтому свойства уровня Exchange 2013 недоступны.
- Дата письма в базе берётся из заголовка `Date`, то есть из времени отправки, и по ней же считается курсор страниц; поэтому отбор и сортировка догрузки идут по времени отправки (комментарии в `ews.rs:648-652` и `ews.rs:665-669`).
- Признак завершения страницы читается из ответа по полю `IncludesLastItemInRange` (`ews.rs:569`).

## Термины и состояния

- Облегчённая выборка - запрос письма без сырого содержимого: только перечисленные свойства и текст письма.
- Минимальное сырое письмо - собранная программой заглушка из заголовков и текста, которая занимает место сырого письма до его скачивания.
- Полное сырое письмо - письмо целиком, как его отдаёт сервер, вместе с вложениями.

## Требования

### S-001. Выборка писем для списка без сырого содержимого

WHEN программа запрашивает у Exchange письма для списка, программа SHALL запросить свойства письма и его текст без сырого содержимого письма.

### S-002. Состав запрашиваемых свойств

WHEN программа запрашивает свойства письма, программа SHALL запросить: тему, время отправки, время получения, отправителя, получателей, получателей копии, признак прочтения, признак наличия вложений, размер, идентификатор письма в сети, идентификатор письма, на которое отвечают.

### S-003. Совместимость с Exchange 2010 SP2

Программа SHALL запрашивать только свойства, доступные при объявленной версии сервера Exchange 2010 SP2.

### S-004. Отрывок текста для списка

WHEN программа получила текст письма, программа SHALL записать в отрывок для списка первые 200 знаков текста без разметки.

### S-005. Минимальное сырое письмо

WHEN программа сохраняет письмо, полученное облегчённой выборкой, программа SHALL записать вместо сырого письма заглушку из заголовков и текста и пометить письмо как письмо без тела.

### S-006. Кодирование заголовков заглушки

WHEN программа собирает заглушку сырого письма, программа SHALL закодировать значения заголовков, содержащие знаки вне набора ASCII, по правилам кодирования заголовков почты и удалить из значений знаки перевода строки.

### S-007. Наличие вложений

WHEN сервер вернул признак наличия вложений, программа SHALL сохранить этот признак у письма; при отсутствии признака в ответе программа сохраняет прежнее значение письма.

### S-008. Дата письма

WHEN программа собирает заглушку сырого письма, программа SHALL записать в заголовок даты время отправки письма, то есть ту же величину, по которой считается курсор страниц догрузки.

### S-009. Скачивание полного письма при открытии

WHEN пользователь открыл письмо Exchange без тела, программа SHALL скачать полное сырое письмо и сохранить его локально.

### S-010. Границы страницы догрузки

WHEN программа догружает письма папки страницами, программа SHALL определять конец выборки по признаку последнего элемента в ответе сервера, а не по числу полученных писем.

### S-011. Отказ на облегчённой выборке

IF сервер отказал в облегчённой выборке свойств, THEN программа SHALL вернуть ошибку с пометкой транспорта Exchange и не подменять её пустым перечнем писем.

## Интерфейсы и данные

- `DiscoveredMessage` получает признак наличия вложений в виде значения "неизвестно" (`Option<bool>`), чтобы облегчённая выборка не затирала прежнее значение письма выдуманным.
- Разбор ответа Exchange дополняется чтением свойств письма; разбор полного сырого письма сохраняется для скачивания по требованию.
- Схема базы и команды Tauri не меняются: используются существующие поля `body_fetched`, `raw_blob_ref`, `preview`, `has_attachments`.

## Ошибки и частичные отказы

- Отсутствие текста письма в ответе не считается ошибкой: отрывок остаётся пустым, письмо сохраняется.
- Отсутствие отправителя в ответе не считается ошибкой: письмо сохраняется с пустым отправителем, как и при разборе сырого письма.
- Ошибка сети при облегчённой выборке возвращается наверх (S-011) и обрабатывается общим порядком синхронизации аккаунта.

## Одновременная работа, повторы и защита от дублей

- Повторная выборка того же письма перезаписывает строку по ключу "папка + идентификатор", дублей не создаёт.
- Письмо, у которого тело уже скачано, не теряет тело при повторной облегчённой выборке: сохранение заглушки не затирает уже загруженное тело.

## Безопасность и конфиденциальность

- Текст письма и заголовки сохраняются в то же зашифрованное хранилище; в журнал содержимое писем не пишется.

## Совместимость, перенос данных и откат

- Уже скачанные письма с телом остаются с телом; перенос данных не требуется.
- Откат к прежней версии оставляет письма без тела: они догрузятся по открытию, потому что докачка по требованию есть и в прежней версии.

## Скорость и потребление ресурсов

- Объём загрузки при построении списка перестаёт зависеть от размера вложений: вместо полного письма скачиваются свойства и текст.
- Число запросов к серверу не растёт: облегчённая выборка выполняется тем же запросом `GetItem` по набору идентификаторов.

## Журналы, метрики и эксплуатация

- Существующая запись о выборке дельты коллекции сохраняется; в неё добавляется число писем, полученных облегчённой выборкой.

## Отклонённые варианты

- `FindItem` со списком свойств вместо `GetItem`. Экономит один запрос, но не возвращает почтовый адрес отправителя, и список остался бы без адресов.
- Свойство "отрывок текста" сервера. Требует Exchange 2013 и версионного конверта запроса с запасным путём для старых серверов.
- Оставить полное сырое письмо при обычной синхронизации и облегчить только догрузку при прокрутке. Основной объём загрузки приходится как раз на обычную синхронизацию.
