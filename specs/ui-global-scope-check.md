# Контроль общей области имён у файлов интерфейса

- Состояние: реализована
- Задача: issue #87
- Обновлено: 2026-09-18
- Ревизия: 1

## Цель и результат для пользователя

Файлы интерфейса подключаются обычными тегами script без сборщика, поэтому все они делят одну область имён. Если два файла объявят на верхнем уровне одно и то же имя через const, let или class, браузер сообщает об ошибке разбора и не выполняет второй файл целиком. Для пользователя это выглядит как отказ половины программы: пропадают умные папки, панель письма и разделы настроек, причём без единого сообщения об ошибке.

Такой отказ не ловится ни одной из существующих проверок: в проверках интерфейса модули читаются через require, где у каждого файла своя область, и столкновение имён там невозможно в принципе.

После изменения столкновение имён находится отдельной проверкой до выпуска, а сообщение называет оба файла и имя.

## Границы задачи

- Чистая логика поиска столкновений: `scripts/ui-global-scope.js`.
- Запуск по файлам репозитория: `scripts/check-ui-global-scope.js`.
- Подключение в сборку и в проверки: `Makefile`, `.github/workflows/ci.yml`.
- Проверки: `apps/desktop/tests/js/ui-global-scope.test.js`.

## Что не входит в задачу

- Перевод файлов интерфейса на модули с собственной областью имён или на сборщик.
- Поиск столкновений имён, объявленных внутри функций и блоков: они в общую область не попадают.
- Поиск повторного объявления одного имени внутри одного файла: это находит сам разбор файла.
- Проверка файлов, которые не подключены в разметке главного окна.
- Разбор языка целиком: проверка смотрит на объявления верхнего уровня построчно.

## Текущее поведение и доказательства

- Файлы интерфейса подключаются обычными тегами script в разметке главного окна (`apps/desktop/ui/index.html`, раздел подключения файлов), сборщика в проекте нет: `package.json` отсутствует.
- Каждый файл объявляет свои значения на верхнем уровне и отдаёт наружу один объект, например `const messageLabels = {...}` в `apps/desktop/ui/modules/message-labels.js`.
- В проверках тот же файл читается через require (`apps/desktop/tests/js/message-labels.test.js`), где у файла своя область, поэтому столкновение имён в проверках не воспроизводится.
- Столкновение уже происходило: имя `ruleLang` было объявлено и в `apps/desktop/ui/modules/mail-rules.js`, и в `apps/desktop/ui/modules/smart-rules.js`, из-за чего второй файл переставал выполняться целиком.

## Термины и состояния

- Файл интерфейса - файл с расширением js, подключённый тегом script в разметке главного окна.
- Общая область - область имён, которую делят все файлы интерфейса, подключённые такими тегами.
- Имя верхнего уровня - имя, объявленное через const, let, var, function или class в строке, начинающейся с первой колонки.
- Столкновение - одно и то же имя верхнего уровня, объявленное больше чем в одном файле интерфейса.
- Владелец имени - файл, объявивший имя первым в порядке подключения.

## Требования

### S-001. Поиск столкновений

WHEN проверка получает перечень файлов интерфейса, программа SHALL сообщить о каждом имени верхнего уровня, объявленном больше чем в одном файле, назвав имя и оба файла.

### S-002. Разные имена

IF имена верхнего уровня всех файлов различны, THEN программа SHALL сообщить об отсутствии столкновений и завершиться успешно.

### S-003. Объявления внутри функций и блоков

WHEN проверка разбирает файл, программа SHALL считать именем верхнего уровня только объявление в строке, начинающейся с первой колонки, и SHALL NOT учитывать объявления с отступом.

### S-004. Виды объявлений

WHEN проверка разбирает строку верхнего уровня, программа SHALL распознавать объявления через const, let, var, function и class, включая объявление генератора со звёздочкой.

### S-005. Примечания и строковые значения

WHEN проверка разбирает файл, программа SHALL NOT считать объявлением слова внутри примечаний и внутри строковых значений.

### S-006. Слова, начинающиеся с ключевого

IF строка начинается со слова, у которого ключевое слово является лишь началом, THEN программа SHALL NOT считать её объявлением.

### S-007. Первый владелец имени

WHEN проверка нашла столкновение, программа SHALL назвать владельцем имени файл, объявивший его первым в порядке подключения.

### S-008. Повтор внутри одного файла

IF имя объявлено дважды в одном файле, THEN программа SHALL NOT считать это столкновением.

### S-009. Пустой файл

IF текст файла пуст или отсутствует, THEN программа SHALL вернуть пустой перечень имён без ошибки.

### S-010. Порядок подключения

WHEN программа собирает перечень файлов для проверки, программа SHALL взять его из разметки главного окна в порядке подключения, а не из перечня каталога.

### S-011. Отсутствующий файл

IF подключённый в разметке файл отсутствует на диске, THEN программа SHALL пропустить его и продолжить проверку остальных.

### S-012. Итог запуска

IF найдено хотя бы одно столкновение, THEN программа SHALL завершиться с ненулевым кодом возврата и объяснить, почему столкновение опасно.

## Интерфейсы и данные

- Чистая логика отделена от чтения файлов: `scripts/ui-global-scope.js` принимает уже прочитанные тексты и возвращает перечень столкновений, поэтому её покрывают проверки без обращения к диску.
- Запуск по репозиторию: `scripts/check-ui-global-scope.js` читает разметку главного окна, берёт из неё порядок подключения и читает сами файлы.
- Проверка подключена целью `check-ui-scope` в `Makefile` и отдельным шагом в `.github/workflows/ci.yml` рядом с проверкой меток версий.

## Ошибки и частичные отказы

- Отсутствие разметки главного окна останавливает проверку с ошибкой чтения файла: без неё порядок подключения неизвестен.
- Отсутствие подключённого файла на диске не считается ошибкой по S-011: такой файл мог быть удалён вместе с подключением в незавершённой правке.

## Одновременная работа, повторы и защита от дублей

- Проверка только читает файлы и не меняет состояние, поэтому повторный запуск даёт тот же результат.

## Безопасность и конфиденциальность

- Проверка читает только файлы репозитория и не обращается к сети; в вывод попадают имена файлов и имена значений, пользовательских данных в нём нет.

## Совместимость, перенос данных и откат

- Новых данных проверка не создаёт, схема базы не затрагивается, откат состоит в удалении двух файлов проверки и её подключения.

## Скорость и потребление ресурсов

- Проверка читает 27 файлов интерфейса один раз и разбирает их построчно, поэтому её время сопоставимо с чтением этих файлов.

## Соответствие требований проверкам

| Требование | Где проверяется |
| --- | --- |
| S-001, S-002 | проверки на двух файлах с одинаковым и с разными именами |
| S-003 | проверка объявления с отступом внутри функции |
| S-004 | проверка всех пяти видов объявлений и генератора |
| S-005 | проверки слова внутри примечания и внутри строкового значения |
| S-006 | проверка адреса со сдвоенной косой чертой и слова, начинающегося с ключевого |
| S-007 | проверка столкновения с третьим файлом |
| S-008 | проверка повтора имени внутри одного файла |
| S-009 | проверка пустого и отсутствующего текста |
| S-010 - S-012 | запуск `node scripts/check-ui-global-scope.js` на репозитории |

## Отклонённые варианты

- Разбирать файлы полноценным разбором языка. Это тянет стороннюю зависимость в проект без сборщика и без списка зависимостей, а построчного разбора объявлений верхнего уровня для задачи достаточно.
- Перевести файлы интерфейса на модули с собственной областью. Это отдельная работа по всему интерфейсу, и она не отменяет пользы от проверки на время перехода.
- Собирать перечень файлов обходом каталога модулей. Значение имеет именно порядок подключения: он определяет, какой файл перестанет выполняться, а обход каталога его не знает.
- Ловить столкновение проверками интерфейса. В них файлы читаются через require, где у каждого своя область, и столкновение не воспроизводится в принципе.

## Открытые вопросы

- Нужно ли расширить проверку на разметку окна уведомлений, у которого свой набор подключённых файлов.

## История решений

- Ревизия 1: проверка заведена после того, как столкновение имени `ruleLang` в двух файлах интерфейса сделало неработоспособной половину программы, а ни одна существующая проверка этого не заметила.
